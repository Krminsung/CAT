# [cat][P10] stdio MCP

## 범위

신뢰가 결정된 workspace에서만 설정된 stdio MCP process를 시작하고, 두 protocol 경로를 섞지
않는 adapter, bounded discovery, host-side JSON Schema 검증과 중앙 permission을 거친 동적 도구를
제공한다. 원본 `src/mcp.ts`, `src/tools.ts`의 MCP 부분과 해당 원본 테스트 계약만 읽으며 원본
script·test·MCP 서버는 실행하지 않는다. streamable HTTP, OAuth, marketplace와 자동 설치는 범위 밖이다.

P09는 검토 head `4033ba63f9cafd576338808b7522b03fbd22012f`를 PR #9에서 merge commit
`e38ef6fa490d8e337042c289f167a5bb438b7fad`로 병합했다. 두 부모와 tree, 조상 관계,
`origin/main` 포함을 확인했으며 병합 뒤 검사는 실행하지 않았다.

## P10.1 구현 메모

- transport는 `shell: false`로 하나의 소유 child를 시작하고 JSON-RPC protocol 의미와 handshake는
  다루지 않는다. 요청 ID와 최대 256개 pending을 추적하며 모든 resolve/reject 경로에서 timer와
  AbortSignal listener를 제거한다.
- stdout은 newline/CRLF frame으로 읽고 frame당 2MiB, JSON 중첩·node 수를 제한한다. 고정 상한까지
  점진적으로 커지는 buffer로 부분 frame을 보존하며 잘못된 UTF-8·JSON·JSON-RPC는 pending 전체를
  실패시키고 transport를 닫는다. stderr는 마지막 64KiB만 보존하고 알려진 secret을 가린다.
- timeout과 abort는 해당 pending을 제거한 뒤 cancellation notification을 best-effort로 보내며 완료된
  요청을 되살리지 않는다. process error/exit/stdin 오류도 남은 pending을 모두 거부한다.
- 종료는 새 요청을 차단하고 pending을 정리한 뒤 stdin close, 제한된 대기, 소유 process group TERM,
  KILL 순서로 진행한다. 외부 PID나 process group은 종료하지 않는다.

## P10.2 구현 메모

- legacy adapter만 `initialize`에서 정확한 `2025-11-25` 응답과 tools capability를 확인한 뒤
  `notifications/initialized`를 보낸다. modern adapter는 legacy handshake를 호출하지 않고 모든 요청의
  `_meta`에 `2026-07-28` protocolVersion, cat clientInfo와 명시적 빈 clientCapabilities를 덮어써
  연결 상태에 protocol 문맥을 의존하지 않는다.
- modern 결과는 누락된 `resultType`을 이전 호환의 `complete`로 받아들이되, 선언된 값은 지원하는
  `complete`만 허용한다. 응답 serverInfo는 표시 metadata로만 보존하고 보안 판단에는 사용하지 않는다.
- discovery는 최대 100페이지, server당 raw entry 10,000개, tool metadata 256KiB, 누적 32MiB와
  cursor 4,096 code point를 제한한다. 잘못된 개별 metadata는 제한된 notice와 함께 제외하거나 다음
  schema 단계에서 비활성화하고, 반복 cursor·전체 상한 위반은 연결 오류로 끝낸다.
- API 이름은 소문자 `mcp__server__tool` 형식으로 만들고 정규화·잘림 충돌 그룹 전체에 원본 server/tool
  identity hash를 붙인다. 정렬과 충돌 처리는 입력 순서와 무관하게 결정적이며 built-in 예약 이름을
  덮어쓰지 않는다.
- 재연결 뒤 늦은 이전 child event가 새 process·pending 상태를 건드리지 않도록 P10.1 listener마다
  현재 소유 child identity도 재확인한다.

## P10.3 구현 메모

- 지원 dialect는 누락 시에도 JSON Schema 2020-12로 고정하며 명시된 `$schema`는 해당 공식 URI만
  허용한다. `ajv@8.20.0`을 exact dependency로 한 번 설치했고 lifecycle script는 실행하지 않았다.
- schema는 128KiB·깊이 24·node 4,000개와 map·분기별 상한을 먼저 확인한다. 문서 내부 JSON
  Pointer `$ref`만 허용하며 remote/dynamic reference, `$async`, `pattern`·`format`·`uniqueItems` 등
  지원 목록 밖 keyword는 조용히 허용하지 않고 해당 도구를 비활성화한다. 내부 `$ref`는 모호한 URI
  인코딩이 없는 제한된 JSON Pointer로 구조 검사에서 확인한 schema 위치만 가리킬 수 있고, 참조를
  따라간 분기 조합도 제한하며 순환 reference는 이번 bounded subset에서 지원하지 않는다.
- provider의 strict 지원 여부에 검증을 맡기지 않는다. 동적 도구 입력은 1MiB·깊이 32·node
  20,000개로 제한한 뒤 mutation/coercion/default 적용이 없는 host Ajv validator를 tool call 정규화와
  중앙 executor 양쪽에서 적용한다. output schema가 선언됐지만 검증할 수 없는 도구도 비활성화한다.
- 동적 도구는 built-in과 분리해 한 번에 교체하고 최대 100개만 노출한다. 서버·protocol·이름·설명·
  입출력 schema의 SHA-256 version을 만들며 manager가 이를 server registry version에 결합한다.
  `allowedTools`의 이름만으로 `mcp__*`를 자동 승인하지 않고 version이 든 external permission과 승인
  scope를 거치게 한다. 서버의 annotations는 표시 metadata일 뿐 승인 근거로 사용하지 않는다.

## P10.4 구현 메모

- user→project→local 순서로 병합되는 `mcpServers` 설정은 command/args/cwd/protocol/disabled와
  environment 변수 이름을 가리키는 secret reference만 저장한다. 전체 parent environment와 model
  credential은 child에 전달하지 않으며 CLI의 add/list/get/remove는 설정만 다루고 process를 시작하지
  않는다.
- 실제 시작은 신뢰 경계를 통과한 대화형 `/mcp reconnect` 또는 같은 중앙 built-in 호출에만 있다.
  승인 scope에는 설정 snapshot, command와 args hash, protocol, 해석한 environment fingerprint,
  canonical workspace path와 cwd의 device/inode가 들어간다. manager가 보유한 workspace identity는
  승인 직전과 각 spawn·registry 교체 전후에 별도로 다시 확인한다.
- manager는 최대 32개 서버와 100개 활성 동적 도구를 관리한다. 재연결 전체 deadline은 5분이고
  server별 연결 실패는 상태로 남기되 취소·identity 변경·정리 확인 실패는 이미 시작한 소유 process를
  닫고 중단한다. disconnect는 독립 adapter를 병렬 정리하며 종료를 확인하지 못한 연결을 남겨 재시도
  가능하게 한다.
- 동적 도구는 host input/output schema 검증, 현재 connection·generation·registry version 재확인과
  `external` permission을 모두 지난 뒤 호출한다. server annotations는 신뢰하지 않고 이름 기반
  `allowedTools`도 external 승인을 생략하지 못한다. 반환 content와 structured content는 알려진 secret과
  민감한 field 이름을 재귀적으로 가린 뒤 공통 출력 상한을 적용한다.
- `list_mcp_servers`, `add_mcp_server`, `remove_mcp_server`와 `cat-tui mcp list|get|add|remove`,
  `/mcp [reconnect]`를 연결했다. 설정 저장·제거·reload는 기존 MCP 연결을 닫되 자동 재시작하지 않으며
  session 전환과 앱 종료도 같은 manager cleanup 결과를 확인한다.

## 정적 코드 검토

P10 base `e38ef6fa490d8e337042c289f167a5bb438b7fad`부터 P10.4와 후속 보완까지 전체 diff를
읽었다. transport와 protocol adapter의 분리, 설정 저장과 process 시작의 분리, workspace·cwd
identity 재확인, 중앙 external permission, 동적 registry의 원자적 교체, reload·session·shutdown
정리 경로를 대조했다.

검토에서 annotation data를 schema처럼 가리킬 수 있던 `$ref`를 구조 검사에서 확인한 schema
pointer로만 제한하고 모호한 URI 인코딩을 차단했다. camelCase와 여러 구분자를 포함한 민감 출력
field 이름을 정규화해 가리고, 승인 화면에 들어가는 command·args·cwd의 Cc/Cf 제어 문자를 거부했다.
transport 직접 생성 경로의 command·cwd byte 상한과 stderr stream 오류 정리도 보완했다. 이 보완은
현재 작업에 포함한다.

MCP→app/TUI 역의존, 중앙 executor 우회, `shell: true`, 검사 script 변경, 추적된 secret·원본 archive·
생성 산출물·GitHub Actions workflow는 발견되지 않았다. `origin/main`은 P10 base와 같고 diff 형식
검사는 깨끗하다. `npm run check`, 실제 MCP process, 앱·TUI와 원본 script·test는 실행하지 않았다.
