# [cat][P10] stdio MCP

## 범위

신뢰가 결정된 workspace에서만 설정된 stdio MCP process를 시작하고, 두 protocol 경로를 섞지
않는 adapter, bounded discovery, host-side JSON Schema 검증과 중앙 permission을 거친 동적 도구를
제공한다. 원본 `src/mcp.ts`, `src/tools.ts`의 MCP 부분과 해당 원본 테스트 계약만 읽으며 원본
script·test·MCP 서버는 실행하지 않는다. streamable HTTP, OAuth, marketplace와 자동 설치는 범위 밖이다.

P09는 검토 head `4033ba63f9cafd576338808b7522b03fbd22012f`를 PR #9에서 merge commit
`e38ef6fa490d8e337042c289f167a5bb438b7fad`로 병합했다. 두 부모와 tree, 조상 관계,
`origin/main` 포함을 확인했으며 병합 뒤 검사는 실행하지 않았다.

## P10.1 구현 메모

- transport는 `shell: false`로 하나의 소유 child를 시작하고 JSON-RPC protocol 의미와 handshake는
  다루지 않는다. 요청 ID와 최대 256개 pending을 추적하며 모든 resolve/reject 경로에서 timer와
  AbortSignal listener를 제거한다.
- stdout은 newline/CRLF frame으로 읽고 frame당 2MiB, JSON 중첩·node 수를 제한한다. 고정 상한까지
  점진적으로 커지는 buffer로 부분 frame을 보존하며 잘못된 UTF-8·JSON·JSON-RPC는 pending 전체를
  실패시키고 transport를 닫는다. stderr는 마지막 64KiB만 보존하고 알려진 secret을 가린다.
- timeout과 abort는 해당 pending을 제거한 뒤 cancellation notification을 best-effort로 보내며 완료된
  요청을 되살리지 않는다. process error/exit/stdin 오류도 남은 pending을 모두 거부한다.
- 종료는 새 요청을 차단하고 pending을 정리한 뒤 stdin close, 제한된 대기, 소유 process group TERM,
  KILL 순서로 진행한다. 외부 PID나 process group은 종료하지 않는다.

## P10.2 구현 메모

- legacy adapter만 `initialize`에서 정확한 `2025-11-25` 응답과 tools capability를 확인한 뒤
  `notifications/initialized`를 보낸다. modern adapter는 legacy handshake를 호출하지 않고 모든 요청의
  `_meta`에 `2026-07-28` protocolVersion, cat clientInfo와 명시적 빈 clientCapabilities를 덮어써
  연결 상태에 protocol 문맥을 의존하지 않는다.
- modern 결과는 누락된 `resultType`을 이전 호환의 `complete`로 받아들이되, 선언된 값은 지원하는
  `complete`만 허용한다. 응답 serverInfo는 표시 metadata로만 보존하고 보안 판단에는 사용하지 않는다.
- discovery는 최대 100페이지, server당 raw entry 10,000개, tool metadata 256KiB, 누적 32MiB와
  cursor 4,096 code point를 제한한다. 잘못된 개별 metadata는 제한된 notice와 함께 제외하거나 다음
  schema 단계에서 비활성화하고, 반복 cursor·전체 상한 위반은 연결 오류로 끝낸다.
- API 이름은 소문자 `mcp__server__tool` 형식으로 만들고 정규화·잘림 충돌 그룹 전체에 원본 server/tool
  identity hash를 붙인다. 정렬과 충돌 처리는 입력 순서와 무관하게 결정적이며 built-in 예약 이름을
  덮어쓰지 않는다.
- 재연결 뒤 늦은 이전 child event가 새 process·pending 상태를 건드리지 않도록 P10.1 listener마다
  현재 소유 child identity도 재확인한다.
