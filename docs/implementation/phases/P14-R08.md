# P14.R08 — 초기 provider 설정과 첫 대화 흐름 보완

## 문제와 변경

v0.1.2는 초기 provider 목록에 custom을 노출했지만 선택 즉시 ConfigurationError로 종료했다.
모델 목록 조회 실패나 빈 목록에서도 CLI 인자를 요구하며 초기 진입을 중단했다.

- 초기 설정과 `/connect`가 공유하는 custom 설정 흐름: base URL, protocol, API 경로, masked API key.
- 잘못된 주소는 입력 화면에 오류를 표시하고 다시 입력한다. HTTP는 명시적 확인 뒤 허용한다.
- 초기 설정 중 취소하면 provider 선택으로 돌아간다. 최상위 provider 선택 취소는 명시적 종료다.
- 모델 목록 미지원·조회 실패·빈 목록에서 모델 ID를 직접 입력한다. `/models`, `/provider`도 같은 흐름을 사용한다.
- 설정 저장·재시작·첫 대화·프로파일 전환을 임시 CAT_HOME과 로컬 모의 API에서 검증한다.
- package와 CLI 표시 버전을 0.1.3으로 맞춘다.

## 사용자 승인과 검증 범위

사용자가 실제 초기 설정부터 사용까지 보완·확인하라는 제안에 “네 그렇게하세요”라고 승인했다.
이 요청에 필요한 컴파일, 로컬 모의 API, 실제 PTY 입력과 문제 발생 시 관련 수정·재검증을 수행한다.
기존 P14.R07의 검사 결과나 예산은 재사용·초기화하지 않는다. 별도 검증 기록을 남긴다.
실제 계정의 API key나 유료 외부 모델 호출은 사용하지 않는다.

확인 대상은 custom Chat/Responses, 입력 오류·취소, 모델 목록 조회 실패/빈 목록, 첫 응답,
저장한 설정 재사용, `/connect`와 `/provider` 전환이다. 전체 제품 기능 검증이라고 표현하지 않는다.

## 소스 실행 검증 결과

- 컴파일 1회 성공 뒤 실제 PTY 검증에서 기본값 커서가 앞에 있어 API 경로가 이어 붙는 결함을 발견했다.
  커서를 기본값 끝으로 옮긴 후 컴파일과 해당 경로·모델 편집 검증을 수행해 통과했다.
- custom Chat 설정, 첫 SSE 응답, 종료 후 저장한 설정 재사용·재응답: 통과.
- 잘못된 URL/credential 포함 URL 거부, 수정·취소 후 provider 재선택: 통과.
- 모델 목록 HTTP 404와 빈 목록 각각에서 모델 ID 직접 입력·첫 응답: 통과.
- Responses와 사용자 지정 API 경로의 저장·실제 요청·첫 응답: 통과.
- `/connect` 새 profile 연결, `/provider` 이전 연결 복귀, `/connect` 취소 후 기존 대화 유지: 통과.
- `/models`에서 기존 모델 ID를 직접 교체하고 새 모델로 요청: 통과.
- 첫 generation 요청 HTTP 401 뒤 앱 유지, 다른 profile 연결 후 대화: 통과.
- 테스트 API key는 가짜 값이며 terminal 출력과 공개 profile에 노출되지 않았다. credential 파일 0600 확인.

최초 자동 검증의 화면 문구 예상 오류(`준비` 대신 실제 `ask`)도 실패 기록으로 보존했다.
상세 실행 기록은 Git common directory의 `cat-progress/P14-provider-setup*`에 보존한다.
설치본 검증: 진행 중.
