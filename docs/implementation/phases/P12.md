# [cat][P12] tasks·worktree·SSH/clipboard

## 범위

session-owned background process, 현재 저장소 안의 managed Git worktree, 사용자 요청에서만 시작되는
OSC52/tmux/SSH clipboard 보조 흐름을 구현한다. 원본 `src/tasks.ts`, `src/worktree.ts`,
`src/clipboard.ts`, `src/ssh-clipboard.ts`, `src/cli.ts`와 관련 원본 테스트 계약만 읽으며 실제 셸·task,
Git worktree 생성·삭제, SSH/PTTY, clipboard와 앱은 실행하지 않는다.

P11은 검토 head `638fcfee9379ca4a5008829351e7449ba53ee034`를 PR #11에서 merge commit
`05a02e75e795e8079b318b2168fc372c50025c7b`로 병합했다. 두 부모와 동일 tree, phase head 조상 관계,
`origin/main` 포함을 확인했고 병합 뒤 검사는 실행하지 않았다.

## P12.1 구현 메모

- `run_command`는 foreground의 `timeout_seconds`와 background의 별도 `deadline_seconds`를 함께 받지
  않는다. 명령 문자열의 단독 `&`는 manager 소유 process group 밖으로 빠질 수 있어 거부하고,
  background 시작도 기존 중앙 command 승인·workspace identity 재검사를 통과한다.
- manager는 canonical workspace hash별 `CAT_HOME/tasks` 하위 0700 저장소에서 16자리 무작위 task ID,
  0600 manifest·log를 사용한다. 한 process의 동시 작업 8개, session 기록 64개, 전체 기록 128개,
  기본 1시간·최대 24시간 deadline과 제한된 복원 scan을 적용한다.
- stdout과 stderr는 32-byte 상태 header가 있는 disk-backed 8MiB 원형 tail에 합치며 read 크기와 tool
  output도 별도로 제한한다. terminal C0/C1 control을 실행 불가능한 문자로 바꾸고 출력 저장·읽기 오류와
  생략 상태를 숨기지 않는다.
- list/read/stop은 현재 session의 task ID 또는 모호하지 않은 prefix만 해석한다. stop 승인은 task ID,
  session, 시작 시각과 command digest를 묶고, 같은 manager가 실제 child reference로 소유한 process
  group에만 TERM→KILL을 보낸다. 임의 PID 입력과 복원된 PID 신호 경로는 없다.
- manifest에는 종료 확인 여부를 기록한다. 재시작 시 확인되지 않은 starting/running/종료 중 기록은
  `stale`로 복원하고 PID를 추측하지 않는다. lifecycle 격리 정리는 현재 process가 만든 task만 종료해
  재개한 session에서 stale 상태를 조회할 수 있으며, manager close 실패는 명시적으로 보고한다.
