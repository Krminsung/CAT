# P14.R10 — 공개 IPv4 주소 오차단 수정

## 요청과 범위

2026-09-28 사용자가 원격 서버의 web_search 실패 원인 확인 후 코드 수정과 업데이트를 요청했다.
공개 IP까지 차단하는 결함을 수정하고 사설·loopback·link-local·metadata 등 기존 보호는 유지한다.
내부망 허용 목록 신설, 권한 완화, 검색 backend 교체, 별도 UI 결함 수정은 이번 범위가 아니다.
기준 main은 `21fd6f8cf46856848b7f93192d4edfd34148d538`(PR #19, 공개 v0.1.4)이다.

## 확인한 원인

원격 v0.1.4 transcript의 세 검색 backend 모두 `web_search_providers_failed`의 diagnostics에
DNS 비공개·특수 목적 주소 차단을 기록했다. 현재 DNS 결과에는 공개 IPv4와 IPv6가 있었다.
원격 `dist/web/public-http.js`와 로컬 공개 v0.1.4 파일의 SHA-256은
`54cb2b74b6ffb4245be14d9a32c462e7f1caad7c87ac9bbe8f2cddc8f01a90f5`로 일치했다.

기존 구현은 하나의 Node BlockList에 IPv4와 IPv6 규칙을 함께 넣었다. IPv4-mapped IPv6 전체를
차단하는 `::ffff:0:0/96`은 Node에서 일반 IPv4 검사에도 적용되어 공개 IPv4까지 차단한다.
사용자가 승인한 원격 진단에서 번들 Node.js v24.21.0의 내장 모듈만 사용해 이 동작을 확인했다.
공개 주소는 해당 규칙 추가 전 false(미차단), 추가 후 true(차단)였다. CAT 앱이나 수정본 실행은 아니다.

## 수정

`src/web/public-http.ts`에서 IPv4와 IPv6 BlockList를 분리하고 `isIP()`가 판별한 주소 family의
목록만 검사한다. 기존 차단 대역은 삭제하거나 완화하지 않는다. mapped IPv6는 IPv6 목록에서 계속
차단하며, 실제 연결 socket의 mapped 주소를 IPv4로 풀어 검증하는 기존 경로도 유지한다.
DNS 결과 전체 검사, redirect마다 검사, 검증 IP 고정 연결, TLS hostname 확인, 프록시 차단,
중앙 권한 처리와 웹 근거 정책은 변경하지 않는다.

## 소스 검토와 검증 상태

두 addSubnet 루프와 `isPublicIpAddress()`의 family 분기가 서로 대응하는지 읽어서 확인했다.
URL·DNS·실제 socket이 같은 판별 함수를 사용하는 연결도 확인했다. 이는 실행 검증이 아니다.

이전 P14 및 후속 작업의 검사·실패 이력을 유지한다. R10 이름으로 새 검사 예산을 만들지 않는다.
사용자의 수정·업데이트 요청은 기록하되, 저장소 지침상 추가 build·runtime·packaging 실행 횟수는
아직 승인되지 않았다. build 1회, 공개/사설 IP 판별 및 실제 웹 검색 검증 1회, packaging 1회,
PR/main 병합·v0.1.5 공개 배포·지정 서버 업데이트와 설치 후 확인 1회에 대한 승인을 요청했다.
승인 전에는 실행·포장·게시·서버 교체를 하지 않는다. 실패 시 추가 승인 없이 재시도하지 않는다.
원격 접속 정보·자격·사용자 대화 원문은 공개 저장소에 기록하지 않는다.

## 배포 절차 승인과 입력 확정

추가 실행과 PR/main 병합·공개 배포·지정 서버 업데이트 범위를 안내한 뒤 사용자가
“pr후 병합해서 배포하세요”로 진행을 지시했다. 안내한 build·웹 검증·packaging 각 1회와
설치 후 확인 1회에 한정하며 실패 시 재시도하지 않는다. 다른 단계의 검사 예산은 그대로 보존한다.
제품 버전은 0.1.5로 올리고 배포 문서를 갱신한다. 의존성·Node runtime·installer 로직은 유지한다.
원격 main은 기준 SHA와 같고 열린 PR·workflow·main 보호·ruleset은 없다. merge commit은 허용된다.
예정 `cat/p14-web-address` 브랜치와 v0.1.5 tag도 없다.

웹 검증은 지정 서버의 임시 경로에 빌드 결과를 준비하고 기존 설치본을 교체하지 않은 상태에서
공개/보호 IP 판별, URL·혼합 DNS 차단, 실제 검색 1회와 검색 결과 원문 1개 조회를 확인한다.
LLM API나 기존 대화·설정·자격 파일은 사용하지 않는다. 테스트 suite와 전체 UI 검증은 반복하지 않는다.
검증용 입력·결과는 ignored local receipt와 임시 경로에 보존하고 비밀값은 기록하지 않는다.
