# [cat][P11] public web와 evidence

## 범위

인증된 model HTTP와 분리된 public-only transport에서 URL·DNS·실제 연결 주소와 redirect를 검증하고,
bounded `fetch_url`·`web_search` 및 evidence-aware web recovery를 중앙 도구·공유 run budget에
연결한다. 원본 `src/tools.ts`, `src/agent.ts`의 web 부분과 관련 원본 테스트 계약만 읽으며 외부 검색,
원본 script·test, 앱과 임시 HTTP server는 실행하지 않는다.

P10은 검토 head `1f1c5d5427dd58f655a9ca4477f1a71d91026ed4`를 PR #10에서 merge commit
`5af2be849c07b8a2752772ce73c090c662a9e008`로 병합했다. 두 부모와 tree, 조상 관계,
`origin/main` 포함을 확인했으며 병합 뒤 검사는 실행하지 않았다.

## P11.1 구현 메모

- URL은 HTTP(S)와 userinfo 없음만 허용하고 localhost·예약 hostname, 비공개·loopback·link-local·
  multicast·unspecified·문서용 IP 및 IPv4-mapped IPv6를 차단한다. DNS 결과는 최대 32개이며 하나라도
  차단 주소이거나 family가 일치하지 않으면 전체 요청을 거부한다.
- 각 hop은 검증한 DNS 주소만 반환하는 lookup을 가진 독립 Undici dispatcher를 사용한다. connector는
  원 URL hostname으로 TLS SNI·인증서를 확인하고 연결 직후 socket remote address가 고정 집합 안인지
  재검사한다. redirect는 수동으로 최대 5회 처리하며 새 host마다 같은 절차를 반복한다.
- 환경 proxy가 있으면 address pinning 우회를 허용하지 않고 요청 전에 실패한다. caller 취소와 transport
  close를 전체 20초 deadline에 결합하고 최대 동시 요청 4개, header 32KiB, wire·해제 body 각 1MiB와
  chunk 16,384개를 제한한다. model API header나 호출자 header는 받을 수 없고 고정 public header만
  전송한다.
- 응답은 본문을 transport 안에서 모두 읽거나 취소한 뒤 per-hop dispatcher를 파기해 raw socket이나
  reader를 상위 계층에 넘기지 않는다. transport close는 활성 요청을 취소하고 정리가 끝날 때까지
  기다린다.

## P11.2 구현 메모

- `web_search`는 알려진 model·저장 credential과 민감한 process environment 값을 소유한 입력 guard에서
  코드 블록, key 할당, bearer/JWT/GitHub token 형태, URL·이메일·IP·로컬 경로를 제거한 뒤 남은 500자
  이하 query만 외부로 보낸다. 동적으로 발견한 MCP secret도 같은 guard에 추가하며 전체 secret을
  검사할 수 없는 상한 상태에서는 검색과 fetch를 fail closed한다.
- `fetch_url`은 알려진 secret이나 key/token/signature 계열 query parameter가 포함된 URL을 실행 전에
  거부하고, 승인 전후 같은 canonical URL인지 확인한 뒤 P11.1 transport만 사용한다. 2xx textual
  response만 decode하며 HTML의 script/style/noscript/svg/template, terminal control을 제거하고 본문,
  title, 실제 final URL과 제한된 링크만 반환한다. 출력은 60,000 code point·192KiB와 40개 링크로
  제한하고 공개 문서를 비신뢰 콘텐츠로 표시한다.
- 검색 backend 순서는 원본과 같이 Bing reader, DuckDuckGo reader, direct Bing HTML이며 각 요청은 한
  번만 실행한다. 추출한 실제 HTTP(S) URL만 결과로 만들고 title·snippet·source host와 backend의 실제
  final URL을 함께 보존한다. 일부 backend 실패는 bounded diagnostics로 드러내며 모두 실패한 경우
  빈 성공이나 합성 결과가 아니라 명시적인 tool failure를 반환한다. 정상 응답에 실제 결과가 없는
  경우와도 구분하며 동일 검색을 반복하지 말라는 결과 계약을 둔다.
- 두 도구는 중앙 `web`/public network permission과 abort signal을 사용한다. model transport의
  credential·header·dispatcher를 받지 않으며 앱 조립 실패와 종료 시 public transport를 별도로 닫는다.

## P11.3 구현 메모

- 사용자가 직접 입력한 prompt를 첨부·로컬 command·hook context와 분리해 최신 공개 정보, 직접 URL,
  명시적 검색, web 금지, 로컬 작업, 민감 context와 위치 없는 날씨 요청을 run 시작 시 분류한다. web
  금지·민감·로컬 경계에서는 web 도구를 노출하지 않고 사용자 위치를 workspace·환경·시간대에서
  추론하지 않는다.
- 공개 검색어는 원 prompt에서 보호 데이터와 검색 지시어를 제거해 host가 한 번 만들며, 모델이 만든
  query 대신 이 실제 값만 중앙 승인·실행·기록 경계로 보낸다. 직접 fetch는 사용자 제공 URL을,
  검색 뒤 fetch는 실제 검색 결과와 이미 연 문서의 제한된 link만 허용한다. 동일 run에서 검색은 한 번,
  canonical URL은 각각 한 번만 실행하며 차단된 재호출은 handler를 시작하지 않는다.
- 검색 snippet은 discovery로만 추적한다. 성공한 `fetch_url`의 비신뢰 본문이 원 query와 관련 있고 최종
  답변이 도구가 반환한 실제 final URL을 인용할 때만 근거가 연결된 것으로 인정한다. web이 사용된 뒤의
  답변과 최신/명시적 web 답변은 완료 전까지 보류하며, 근거 없는 모델 초안은 화면·message transcript에
  남기지 않는다.
- 근거가 빠진 완료 후보에는 P05의 동일 run recovery budget에서 `web` 복구를 최대 한 번 소비한다.
  이미 검색했다면 재검색하지 않고 발견 URL fetch, 기존 원문 인용 또는 정직한 근거 부족 응답만
  요청한다. 복구 뒤에도 근거가 없거나 도구가 없으면 host가 제한 문구를 반환하며, 위치 없는 날씨는
  복구 예산과 외부 요청 없이 지역을 다시 묻는다. public page 결과는 native tool role 또는 명시적인
  비신뢰 data delimiter 안에만 전달하고 system 권한이나 permission으로 승격하지 않는다.
