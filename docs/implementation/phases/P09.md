# [cat][P09] AGENTS·skills·commands·hooks

## 범위

전역 지침과 신뢰된 프로젝트 지침, lazy skill·markdown command, 정확히 8개 command hook을
bounded 입력·출력·실행 예산 안에서 제공하고 agent·중앙 executor lifecycle에 연결한다. 원본
`src/context.ts`, `src/extensions.ts`, `src/hooks.ts`, `src/trust.ts`의 해당 계약만 읽으며 원본
script·hook·앱·테스트는 실행하지 않는다. MCP process는 P10, background process는 P12에 남긴다.

P08은 검토 head `ea3d36304e4144bce323a100680edb32df23d379`을 PR #8에서 merge commit
`7d86fdd05dbb3387008e2c81ef8a25f0a0f3920f`으로 병합했다. 두 부모와 tree, 조상 관계,
`origin/main` 포함을 확인했으며 병합 뒤 검사는 실행하지 않았다.

## P09.1 구현 메모

- canonical 전역 이름은 `AGENTS.override.md`, `AGENTS.md`이고 같은 디렉터리에서는 override가
  우선한다. 설정된 호환 fallback은 그 뒤에만 적용하며 프로젝트는 Git root부터 현재 workspace까지
  각 디렉터리에서 하나씩 선택한다.
- 사용자 소유 `CAT_HOME` 지침은 별도 범위에서 읽고, 프로젝트 파일은 workspace trust가 확정된
  경우에만 내용 탐색을 시작한다. 로드된 프로젝트 텍스트는 권한을 부여하지 않는 비신뢰 입력이다.
- `@path`는 전역 또는 project root canonical 경계 안의 `.md`, `.markdown`, `.txt`만 읽는다.
  중복·순환을 같은 canonical 경로 집합으로 차단하고 최대 깊이 5, 파일 32개, 기본 전체 32KiB와
  UTF-8·NUL·경로 크기 제한을 적용한다. 생략과 truncation은 구조화된 notice로 보존한다.

## P09.2 구현 메모

- `CAT_HOME` 확장 metadata는 항상, 프로젝트 `.cat/commands`와 `.cat/skills`는 trust가 확정된
  경우에만 수집한다. catalog에서는 최대 64KiB header만 읽고 전체 Markdown 본문은 실제 command나
  `load_skill`이 선택됐을 때 최대 256KB 범위에서 읽는다.
- command는 제한된 재귀 경로를 `:` 이름으로, skill은 바로 아래 디렉터리의 `SKILL.md`로 식별한다.
  built-in 28개 이름과 충돌하면 오류를 기록하고 built-in을 보존하며 symlink, 과도한 디렉터리·파일 수,
  잘못된 UTF-8·frontmatter·이름을 catalog에서 제외한다.
- `load_skill`은 모델 입력을 정규화한 이름으로 catalog에서만 조회하며 입력을 filesystem 경로로 쓰거나
  다운로드·설치·script 실행을 하지 않는다. Markdown command의 `$ARGUMENTS`, `$1`–`$9` 치환도
  streaming byte 상한 안에서 렌더링해 반복 치환에 따른 무제한 메모리 확장을 막는다.

## P09.3 구현 메모

- 설정 parser와 engine은 `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`,
  `PostToolUseFailure`, `Stop`, `PreCompact`, `SessionEnd`만 허용한다. group·hook·matcher·command와
  timeout 수·형식·크기를 제한하고 engine 전체 재진입을 거부한다.
- command는 `/bin/sh -c`로 실행하되 최소 child environment만 전달하고 API key, token, proxy,
  shell injection 변수를 상속하지 않는다. stdin JSON은 1MB, stdout+stderr는 256KB, context는 64KB,
  notice는 64KiB로 제한하며 timeout·abort 시 소유 process group을 단계적으로 종료한다.
- exit code 2는 `UserPromptSubmit`·`PreToolUse`·`Stop`에서만 block 의미를 갖는다. `PreToolUse`의
  구조화된 deny도 추가 거부로만 사용하고 allow 출력은 기존 permission을 넓히지 않는다. post hook
  실패는 중앙 executor 경고로만 남아 완료된 handler를 다시 실행하지 않는다.

## P09.4 구현 메모

- trust가 결정된 뒤 지침과 확장 metadata를 조립하고 `load_skill`을 중앙 registry에 등록한다.
  지침·skill catalog·SessionStart/UserPromptSubmit context는 권한을 부여하지 않는 비신뢰 입력으로
  명시해 모델 context와 분리하며 Markdown command 본문은 실제 호출 시에만 읽는다.
- 중앙 executor에는 Pre/Post hook을, agent에는 공유 run 예산을 소비하는 최대 1회의 Stop continuation을
  연결한다. SessionStart/SessionEnd는 최초 실행·재개·새 세션·fork·reload·종료 경계에서 실행하고,
  PreCompact와 UserPromptSubmit도 단일 소유 실행 경로에 연결한다.
- `/init`은 기존 `AGENTS.md`를 절대 덮어쓰지 않는다. `# instruction`은 canonical 경로 확인과 UTF-8·크기
  제한, 파일 관찰, 중앙 `write_file` 승인·재검증·checkpoint·hook 경계를 거쳐 append한다. trust 전 새로
  만든 프로젝트 지침은 같은 실행에서 로드하지 않고 다음 실행의 명시적 trust 확인을 기다린다.
- `/reload`는 project trust를 다시 추론하거나 인증·기존 승인을 초기화하지 않는다. 같은 trust 범위에서
  설정·지침·command·skill·hook을 먼저 검증한 뒤 교체하고, mutable tool 정책만 기존 승인 상태를 보존한
  채 갱신한다. autocomplete와 `load_skill`은 교체 가능한 catalog reference를 지연 조회한다.

## 정적 코드 검토

- base main부터 P09.4까지 전체 diff를 대조해 project trust 이전에는 프로젝트 지침·extension body·hook
  process를 읽거나 실행하지 않고, PreToolUse가 중앙 permission을 확대하지 않으며 PostToolUse 실패가
  완료된 handler를 반복하지 않는 경계를 확인했다.
- Stop continuation은 같은 runner와 `RunBudgetController`에서 recovery와 continuation을 각각 소비하고
  `NORMALIZE → MODEL` 전이는 이 경로에서만 사용한다. 두 번째 block 또는 남은 공유 예산 부족은 새
  모델·도구 실행 없이 `budget_exhausted`로 끝난다.
- 정적 검토에서 깊은 root→cwd 경로가 기본 지침을 파일 수 상한 전에 모두 선로딩하는 문제를 찾아 기본
  문서 선택 자체를 32개로 제한했다. 반복된 include 오류의 notice도 256개에서 제한해 진단 배열이
  입력 크기에 비례해 무제한 증가하지 않게 했다.
- lazy command·skill 본문이 catalog 뒤 같은 byte 크기로 교체되는 경우를 찾아 device·inode·size·mtime·
  ctime identity를 본문 open 직후와 read 뒤에 다시 확인한다. 지침과 extension read는 `O_NOFOLLOW`와
  non-blocking open, read 전후 경로·파일 identity를 함께 확인한다. 긴 skill catalog는 완전한 이름 행만
  보존해 잘린 가짜 이름을 모델에 노출하지 않는다.
- 이 보완은 현재 정적 검토 수정으로 확정할 예정이다. compiler, 앱, TUI, hook, extension body와 원본
  script는 실행하지 않았다.
