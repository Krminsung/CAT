## 범위와 기준

사용자가 개별 오류 보고를 기다리지 않고 관련 사례를 함께 보완해 수정하도록 요청했다.
기준 main은 `8a3bc407d64271b9640f2161b2da4e0aaf8288a5`이다. R11은 PR #21로 병합되어
공개 v0.1.6으로 게시됐다. 실제 완료 근거는 해당 PR 댓글과 ignored v0.1.6 publication receipt다.
이를 재실행하지 않는다. 현재 단계는 새 검사 예산을 의미하지 않는다.

v0.1.6의 읽기 전용 진단에서 붙여 쓴 지역명·날씨 질문이 하나의 검색 anchor가 되어 결과를
전부 제외하는 경로를 확인했다. 사용자의 서버 식별자·대화 원문·인증정보는 기록하지 않는다.

## P14.R12.1 — 공통 날씨 표현 분리

- 도시별 예외 목록을 추가하지 않고 날씨·기온·강수량·강수확률·체감온도·습도 같은 알려진
  날씨 명사를 경계로 지역명과 주제를 분리한다. `날시`는 이 주제 경계에서 `날씨`로 정리한다.
- 명사 앞뒤에 붙은 오늘·내일·모레 등의 시간 표현, 조사와 요청 말투의 짧은 접미부를 분리한다.
- 한글 단어 80자, 대화 접미부 16자 범위에서만 처리하며 외부 서비스·새 형태소 라이브러리를
  추가하지 않는다. 지명 철자를 추정해 바꾸지 않는다.
- 날씨의 지역 anchor에서 시·군·구/특별시·광역시 등 행정 접미부를 분리해 지역명이 같은
  짧은 표기와 대응한다. 일반 제품·버전 식별자에는 적용하지 않는다.
- 기존 query guard 뒤의 정규화를 사용하므로 검색·검색 결과 필터·원문 근거·지역 누락 판단이
  같은 표현을 사용한다. secret 재확인, 실제 원문·최종 URL 인용 조건과 권한 경계는 유지한다.

## 실행하지 않은 작업

소스 작성·읽기와 Git 변경 확인만 수행한다. build/check/test, 임시 runner, 앱·원격 웹·모델 API·
설치본 실행, 포장, push/PR/merge/Release, 서버 교체는 별도 지시 없이 진행하지 않는다.
소스 검토를 런타임 검증 통과로 표현하지 않는다.

## 관련 입력과 유지할 경계 (실행 결과가 아닌 소스 검토 기준)

| 입력·상황 | 의도한 처리 |
|---|---|
| `광주날씨`, `광주 날씨`, `광주의날씨는` | 지역 광주와 날씨 주제를 분리 |
| `오늘광주날씨어떄요`, `광주내일날씨좀알려주세여` | 시간·요청 표현을 분리하고 같은 지역 anchor 유지 |
| `광주시날씨`, `광주광역시 날씨` | 같은 광주 anchor로 원문의 짧은 지역 표기와 대응 |
| `오늘날씨어때요`, `내일날시알려주세요` | 지역 없음으로 판단하고 질문; 날짜·말투를 지역으로 오인하지 않음 |
| `광주기온은`, `광주강수확률알려주세요`, `광주체감온도` | 관련 날씨 명사를 지역명과 분리 |
| NFC/NFD·한영 혼합·붙여쓰기와 대화 표현 오타의 조합 | 동일한 query/anchor 생성 경로 사용 |
| 다른 도시의 원문, 지역명만 있는 비날씨 페이지, URL만 일치 | 근거로 무조건 통과시키지 않음 |
| 웹 사용 금지, secret 포함, 권한 거부, 검색만 성공·인용 누락 | 기존 금지·근거 조건 유지 |
| domain·URL·버전·일반 제품명 | 지명 추정이나 일반 목적 fuzzy 교정으로 바꾸지 않음 |

도시별 별칭·잘못 쓴 지명 추정·여러 행정구역을 임의로 붙인 주소의 완전한 해석·임의 문장 전체의
형태소 분석은 범위가 아니다.
검색 서비스의 실제 응답과 날짜·수치의 정확성은 이 소스 검토로 확인됐다고 주장하지 않는다.

## P14.R12.2 — 0건 원인과 완료 상태 표시

- P14.R12.1 커밋: `d3562f023707f3828dabac3020f54e7ce1f9ecbc`.
- 검색 backend가 실제 URL을 주지 않은 경우와 URL은 있었지만 관련성 필터가 모두 제외한 경우를
  `no_results` / `no_relevant_results`로 구분한다. 후자의 backend·입력 결과 수·남은 결과 수를
  기존 diagnostics 안에 기록하되 사용자 원문이나 비밀정보를 새로 추가하지 않는다.
- 결과 URL이 하나도 없어 원문을 열 수 없는 상태에서는 추가 모델 복구를 요구하지 않는다.
  재검색 상한을 늘리거나 근거를 만들어내지 않고 원인에 맞는 한계 안내를 반환한다.
- 검색 완료 행에 실제 결과 건수 또는 관련 결과 0건을 표시한다. 다른 도구도 종료 시 진행 중
  요약을 제거해 `완료 · 진행 중` 같은 모순된 표시가 남지 않도록 한다. 원문 세부 출력은 보존한다.
- 성공한 검색이 실제 원문 조회와 인용 없이 답변 승인으로 바뀌지 않는다. 기존 로그에 새 필드가
  없어도 읽을 수 있으며 오래된 결과는 기존 근거 부족 안내를 유지한다.

관련 표시·진단 검토 기준에는 backend 실패, 전체 필터 탈락, 정상 검색 1~10건, 검색 0건,
실패·거부·취소, 완료 후 늦은 progress event와 이전 세션 복원을 포함한다. 실제로 실행하지 않았다.

## 한 차례 소스 검토와 보존

공통 정규화 함수와 query/evidence 연결, `SearchAttempt` 결과 타입·세 backend 경로,
runner의 `use_host_limitation` 처리, TUI의 live/restore 종료 경로를 읽어 확인했다.
관련 표기를 함께 검토하면서 `일기예보`·`기상예보`를 완전한 주제 명사로 처리해 `일기`·`기상`을
지역 anchor로 오인하지 않도록 반영했다. TypeScript 설정·의존성·권한·URL/DNS·인용 계약은
변경하지 않았다. `git diff --check`의 공백 오류는 없으며 이는 컴파일 또는 실행 검증이 아니다.
