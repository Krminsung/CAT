# [cat][P05] 단일 소유 bounded agent loop

## 범위

한 사용자 입력을 하나의 session/run owner가 맡고, 모델 첫 요청·transport 재시도·도구·복구와
wall-clock을 공통 예산으로 제한하는 실제 모델→도구→모델 흐름을 구현한다. 원본
`src/agent.ts`, `src/types.ts`, 관련 agent/tool 테스트의 계약만 읽었으며 원본 테스트는
실행하지 않는다. web, compaction과 hook 실행은 후속 단계 범위이고 이번 단계에서는
공통 예산을 소비할 port만 둔다.

P04는 PR #4의 head `dec139826157fa12b2b6aeb0a001c80469392c3f`를 merge commit
`b2c3bdb562c1a67d4191fec17bfd04a5f0e41663`로 병합했고 tree·부모·`origin/main`
정합성을 확인했다. 이 커밋이 P05의 기준 main이다.

## P05.1 구현 메모

- session coordinator는 기존 run을 유지한 채 같은 session의 새 run을 `concurrent_run`으로
  거절한다. 임대 해제는 token을 대조하고 한 번만 성공한다.
- 상태는 `PREPARE → MODEL → NORMALIZE → AUTHORIZE_TOOLS → MODEL 또는 FINISH`의 허용된
  간선만 통과한다. terminal reason은 한 번만 기록된다.
- 기본 예산은 turn 12, 실제 모델 요청 24, 도구 40, 복구 전체 2·같은 종류 1,
  compaction 1, Stop continuation 1, wall-clock 10분이다. 모든 override는 제한된 안전 정수다.
- 모델의 첫 요청과 transport의 각 HTTP 재시도는 같은 `modelRequests` 값을 소비한다.
  compaction과 Stop continuation은 전용 상한뿐 아니라 공통 복구 예산도 함께 소비한다.
- caller 취소와 wall-clock 만료는 하나의 하위 signal로 전파한다. timer·listener와 run lease는
  멱등적으로 정리하며 실제 agent loop는 P05.3에서 연결한다.

## P05.2 구현 메모

- native call이 있으면 그것만 사용한다. text fallback은 응답 전체가 `call:<name> <object>`
  호출 하나 이상으로만 구성됐을 때 해석하므로 코드 펜스·인용문·설명 속 예시는 실행되지 않는다.
- strict 모드는 표준 JSON만 허용한다. 명시적 relaxed 모드는 single quote, bare object key와
  제한된 scalar만 작은 bounded parser로 읽으며 `eval`, 함수, 임의 identifier 값은 허용하지 않는다.
- call ID는 응답 안과 run의 이전 응답 전체에서 먼저 중복 확인한다. 중복 batch는 어떤 도구도
  실행하지 않으며 native call이 없는 경우에만 fallback을 고려한다.
- 등록된 provider schema로 입력을 검증하고 복제·동결한다. 한 batch의 올바른 호출과 잘못된 호출을
  구분해 올바른 호출 결과와 제한된 교정 feedback을 함께 다음 모델 turn으로 전달할 수 있다.
- 실행 ledger는 중앙 executor가 handler 직전에 알리는 시점만 `started`로 기록한다. 결과는
  `completed`, `not_started`, `failed`, `unknown`, `denied`, `cancelled`를 보존하며 시작 뒤 결과를
  잃으면 `unknown`으로 닫는다.

## P05.3 구현 메모

- owner loop는 provider 첫 요청을 직접 소비하고 완료된 stream을 정규화한 뒤, 기본 순차 방식으로
  중앙 executor를 호출해 결과를 다음 local conversation의 tool feedback으로 연결한다.
- text stream은 일반 답변이 `call:` prefix가 아님이 확인되는 즉시 event로 내보낸다. 호출 가능성이
  있는 완성 메시지는 정규화 뒤에만 공개해 fallback protocol 본문을 사용자 text로 흘리지 않는다.
- permission policy와 runner가 같은 interaction hub를 사용하면 approval event에 현재 call ID가
  붙는다. decision port가 없거나 취소되면 policy가 실행 전 거부·취소 결과로 닫는다.
- `update_plan`은 session별 계획과 `plan_update` event를 함께 갱신한다. user-input decision port가
  연결된 경우에만 `request_user_input`을 등록하고 질문·선택·결과 event를 같은 run에 기록한다.
- provider usage를 run 전체로 합산하며 모든 tool result는 모델 전달 전 turn 총량으로 다시 제한한다.
  handler 시작 뒤 결과가 유실되면 `unknown`이고, 승인 거부나 취소 뒤 batch의 남은 handler는
  실행하지 않는다.
- event sink 예외는 모델 재시도를 만들지 않는다. 모든 terminal 경로에서 `run_end`는 한 번이고
  interaction attachment, wall-clock timer와 session/run lease를 정리한다.

## P05.4 구현 메모

- call ID와 무관하게 canonical tool 이름·입력과 canonical 결과가 연속 두 번 같으면 세 번째
  동일 호출을 handler 시작, tool budget 소비와 승인 전에 `no_progress`로 종료한다.
- 반복 차단이나 앞선 승인 거부·취소로 실행하지 않은 batch 항목은 구조화된 `not_started`,
  `denied`, `cancelled` 결과로 닫는다. permission denial은 즉시 terminal이므로 다른 도구로
  동일 작업을 우회할 다음 모델 turn이 없다.
- unknown tool, schema 오류와 malformed fallback은 하나의 `malformed_tool_call` 복구 종류다.
  한 응답의 올바른 호출은 실행할 수 있지만 교정 feedback은 run당 같은 종류 한 번뿐이다.
  두 번째 교정 시도는 새 provider 요청 없이 공통 복구 예산 소진으로 종료한다.
- provider 호출을 감싸는 retry loop는 없고 transport만 제한된 HTTP retry를 소유한다.
  P06 compaction, P09 Stop hook과 P11 web 복구가 현재 run의 signal, deadline, 모델·도구와
  종류별 복구 예산을 공유하도록 `AgentExtensionBudgetPort` 계약을 제공한다.

## 정적 코드 검토

`origin/main...552d8ae`의 전체 diff를 한 차례 읽었다. session/run 단일 소유권,
상태 전이, 모델·transport·도구·복구의 공통 예산, native 우선 호출 정규화, call ID
중복 제거, 실행 원장, 중앙 executor, 상호작용 event, permission denial과 반복 실행
차단을 기능 계약에 대조했다.

검토 중 agent와 provider event 수, native 호출별·turn 전체 byte에 상한을 추가하고
provider usage와 native 호출은 도착 시점의 bounded 복제본으로 고정했다. 작은 delta로
나뉜 text fallback prefix는 이미 읽은 전체 문자열을 반복 탐색하지 않게 선형 처리했다.
모든 terminal 경로는 interaction, timer와 session lease를 먼저 멱등적으로 정리해
`run_end` sink가 같은 session의 다음 run을 재진입시킬 수 있게 하고, 마지막 event 자리를
항상 남겨 `run_end`를 한 번 기록한다. 이 보완은
`552d8ae8bd0788f87c5f5c27438fdf16c3a01363`에 묶었다. 이후 `origin/main`이 기준
`b2c3bdb562c1a67d4191fec17bfd04a5f0e41663`과 같음을 다시 확인했다.

TypeScript 검사 무시 지시, `any` 타입 우회, 추적된 secret·원본 archive·build 산출물,
GitHub Actions workflow는 발견되지 않았다. 정적 검토만 수행했으며 모델, 도구, 승인과
취소 흐름의 실제 런타임 동작을 검증했다고 주장하지 않는다.
