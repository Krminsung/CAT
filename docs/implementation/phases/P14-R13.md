### 기준선 밖과 남은 확인

기존 이관 기준에서 Anthropic 계정/OAuth·구독, claude.ai 원격 세션, vendor telemetry,
marketplace, 음성·브라우저·Windows 전용 계층은 제외됐다. 제품 내부 다중 agent·daemon도 현재
계약에 없다. 해당 기능이 CAT에서 된다고 표시하지 않으며, 최신 공식 제품의 모든 기능까지
지원한다고 확대 해석하지 않는다. 정확한 동등성 판정에는 동일한 사용자 시나리오의 실행 비교가
필요하다. 모델의 추론 품질과 공급자별 API 기능 차이도 하네스 소스만으로 보장하지 않는다.

## 구현·검토 기록

### P14.R13.2 — 검색어·출처·대안 요청

- 모델 query를 유지하고 기존 secret/경로/주소/크기·중첩 인코딩 검사를 적용한다. 날씨나 말투
  정규화로 query를 다시 쓰지 않는다. 검색 anchor는 순서 결정에만 쓰며 0점 후보도 보존한다.
- 명시적인 `site:` 범위만 제외 기준으로 유지한다. 0건은 backend 미발견과 domain 범위 불일치를
  구별하며 원문 관련성은 모델이 실제 본문을 보고 판단한다.
- 실제 성공한 fetch의 비어 있지 않은 본문과 최종 URL을 근거 기록으로 삼는다. lexical score를
  의미 정확성 검사라고 취급하지 않는다. 인용 연결은 사실적 주장 전체의 진실성 인증이 아니다.
- 검색과 fetch를 합쳐 8회, 같은 정규화 검색어/URL의 반복은 차단한다. 다른 query·공개 URL은
  중앙 executor를 통해 선택할 수 있다. batch 중에도 실행 직전 한도를 다시 확인한다.
- 비밀정보/외부 전송 금지/권한 거부/DNS·redirect/공유 run 예산은 유지한다. 실제 거부 뒤 대안
  경로를 허용하지 않는다. 도구 공개 여부가 네트워크 실행 승인을 대신하지 않는다.
- 도구 완료 행의 결과 수와 오래된 로그의 `no_relevant_results` 표시 호환을 유지한다.

query guard → normalizer → 실행 직전 제한 → executor → 결과 관찰 경로와 source diff를 읽었다.
다음 작업에서 대화·최종 답변 분류를 연결한다. build/check/runtime은 실행하지 않았다.

### P14.R13.3 — 대화·최종 답변·실제 도구 능력

- 내부 최종 응답을 `answer/direct/clarification/unavailable`과 사용자용 `text`로 구분한다.
  완성된 두 필드 JSON만 해석하고 tool call이나 권한으로 실행하지 않는다. 일반 텍스트를 반환하는
  provider 호환은 유지한다. 최종 사용자 화면·transcript에는 해석한 본문을 전달한다.
- 일반 설명·로컬 결과, 맥락상 필요한 질문, 실제 조회 실패의 구체적인 설명을 보존한다. 최신/외부
  답변은 실제 조회 URL 인용을 요구한다. 한 번도 조회하지 않은 허위 조회 불가 응답은 복구 대상으로
  남긴다. 첫 실패 후 원문이 없고 예산이 남으면 대안을 한 번 안내하며, 실제 한계 설명은 그 뒤
  그대로 보존한다. 안전한 의미 판단 전체를 host가 증명한다고 주장하지 않는다.
- 날씨 지역/anchor 없음에 따른 도구 비활성화와 고정 질문 대체를 제거했다. 로컬·일반 대화라는
  분류는 기본 힌트이며 공개 문서 도구를 숨기지 않는다. 필요한 대상은 모델이 bounded history에서
  해석한다. 금지·민감 입력과 `allowTools=false`는 계속 실제 도구 경계를 제한한다.
- 최근 사용자 대화 최대 32개에서 명시적 웹 금지를 이어받고, 나중의 명시적 웹 요청이 있어야
  해제한다. 이 범위를 벗어나거나 압축으로 빠진 문맥까지 영구 정책으로 저장하는 기능은 아니다.
- CAT의 파일·셸·stdio MCP 능력과 요청 유형별 실행 범위를 system prompt에 명시했다. 실제
  노출 도구가 있는데 아무 도구도 실행하지 않고 접근 불가를 답한 경우 최대 1회 capability 안내를
  한다. 기존 공통 복구 2회 안에서만 사용하며 새로운 실행/권한을 자동 승인하지 않는다.
- 모델/turn/복구 예산이 이미 소진된 때 불필요한 복구를 예약하지 않는다. 새로운 timer나 재귀
  agent 실행은 없다. 실제 도구 거부·취소 시에는 기존 즉시 종료 경로를 유지한다.
- JSON으로 시작하는 응답은 fallback 비활성/웹 금지 상태에서도 완료까지 보류하여 내부 메타데이터
  조각이 화면에 먼저 나오지 않게 했다. 일반 로컬 도구의 진행 설명을 웹 초안으로 일괄 폐기하지 않는다.
- 현재 UTC 시각을 model context에 제공하되 서버의 위치/시간대를 사용자 위치로 간주하지 않는다.

| 직접 URL, redirect, 검색에서 얻은 URL | 실제 fetch 본문·최종 URL만 인용 기록, 다른 페이지로 원문 확인을 가장하지 않도록 지시 |
| 대화의 웹 금지, secret/인코딩/사설 URL, 거부·취소 | 기존 전송·권한·transport 경계 유지; 다른 도구로 우회 금지 |
| 실제 도구 없음/이미 실행 실패/권한 거부 | capability 안내로 도구를 추가하거나 실패를 성공으로 바꾸지 않음 |
| kind/text JSON, 일반 본문, 사용자가 요청한 코드/JSON | 완전한 메타데이터만 해석, 내용은 실행하지 않음, 본문을 저장 |
| plain provider의 의미 분류, 모든 언어의 오타 | 구조화 지침 준수와 의미 정확성은 모델 의존; 완전 보장하지 않음 |

새 파일·타입과 import, native/text call 정규화, batch 실행 제한, 결과 관찰, 최종 표시/저장,
복구의 state 전이와 공유 예산을 한 차례 읽어 검토했다. redirect의 최종 URL도 이미 조회한
대상으로 기록해 같은 원문을 곧바로 다시 조회하지 않도록 했다. `git diff --check`는 공백 검사일 뿐
TypeScript 검사/실행 검증이 아니다. 이전 v0.1.6 dist와 설치본은 이 변경을 포함하지 않는다.

## 후속 푸시·배포 요청 — 버전 입력 승인 대기

2026-09-29 사용자가 푸시와 배포를 요청했다. 원격 읽기 확인 결과 공개 저장소 `Krminsung/CAT`의
push 권한과 merge commit 방식이 허용되며, workflow·ruleset·main protection·열린 PR은 없다.
원격 main은 기존 기준 `8a3bc407d64271b9640f2161b2da4e0aaf8288a5`와 같고, 예정 브랜치
`cat/p14-harness-flow`와 `v0.1.7` 태그는 없다. 활성 로컬 Git hook도 없다.

현재 `src/core/version.ts`, `package.json`, root lockfile 버전은 `0.1.6`이며 이 버전은 이미
공개 Release로 배포됐다. packager는 package 버전으로 installer 이름과 payload 버전을 만들고,
`install.sh`는 Release 태그와 같은 버전의 asset 이름을 요구한다. 버전 override 기능은 없다.
기존 공개 v0.1.6을 덮어쓰거나 v0.1.7 태그 아래 이름·내부 버전이 다른 파일을 게시하지 않는다.

정상 배포에는 v0.1.7 버전 입력과 관련 배포 안내를 정리한 뒤 추가 build 1회가 필요하다.
이 변경은 검사 후 입력 동결 규칙에 해당하므로 사용자의 명시적 추가 승인을 요청한다.
현재 상태는 `BLOCKED_REVIEW`이며 앞선 build PASS와 모든 실행 예산 기록을 유지한다.
이번에는 진행 문서만 변경했다. 버전/실행 코드 변경, 추가 build/check/runtime, 포장, push·PR·
병합·Release 및 서버 반영은 수행하지 않았다. 승인 후 기존 빌드 반복을 가장하지 않고 별도
예약·결과를 기록한 다음 포장과 이미 요청된 원격 게시를 진행한다.

## P14.R13.4 — v0.1.7 배포 입력과 추가 승인

사용자가 위 버전 변경·`npm run build` 추가 1회 및 포장→푸시→PR/main 병합→공개 배포 제안에
`네 변경하세요`로 승인했다. 기존 승인 대기는 해소하되 앞선 1회 PASS 기록은 그대로 보존한다.
CLI 버전과 package/lockfile의 프로젝트 버전, README·설치/Release 안내만 v0.1.7 기준으로
정리했다. 의존성·Node runtime·컴파일러·installer/bootstrap·하네스 기능 코드는 변경하지 않는다.
diff를 읽어 버전 일치와 기록의 검증 범위를 확인했다. 원격 main 기준도 이전과 같다.

추가 build 1회와 이후 비재귀 포장 1회만 수행하며 새 check/test/app/API/설치본 실행은 하지 않는다.
포장 전 기존 v0.1.6 artifacts는 `.git/cat-progress/artifacts-v0.1.6-before-v0.1.7`로 보존한다.
새 빌드가 통과하면 모든 실행/배포 입력을 다시 고정한다. 병합 뒤 Git 정합성만 확인하고 재빌드하지
않는다. 공개 Release와 원격 서버 설치는 별개이며 이번에 서버를 교체하지 않는다.
