# [cat][P03] provider와 streaming transport

## 범위

Responses와 OpenAI Chat 호환 API를 공통 provider event로 변환한다. 인증된 모델
transport의 HTTP/SSE, adapter 두 종류, 13개 provider catalog와 capability를
구현한다. 원본 `src/api.ts`, `src/providers.ts`, `src/http.ts`, `src/errors.ts`와
관련 provider/API 테스트의 계약만 읽었으며 실행하지 않았다.

## 정적 코드 검토

`origin/main...22e77eb`의 전체 diff를 한 차례 읽었다. 공통 provider event와
protocol별 message 변환, streaming tool call의 ID·index·완료 시점, usage와 종료
marker, 같은 origin의 인증 redirect, transport 단독 retry와 공통 budget, deadline과
reader 정리, 모델 목록의 크기·개수 제한 및 수동 ID 경로를 대조했다.

검토 중 deadline timer의 응답 수명 결합, 명시한 proxy 환경과 process 환경의 격리,
SSE의 UTF-8 byte·물리 구분자·chunk 계산, 입력 content/item 수, Responses tool call
별칭 결합과 usage 형식, Chat의 단일 선택지 정규화, catalog와 profile 결합 검증을
보완해 `22e77eb5ca0b4e8b05432dc221cec441a5a92c3d`에 묶었다. 이후
`origin/main`이 기준 `2429b419dc403132a69c4c9883b8dd374c284996`과 같음을
다시 확인했다.

두 adapter는 원격 response chain 없이 로컬 transcript에서 요청을 만들며, 완성된
tool call은 protocol의 전체 완료 뒤에만 공통 event로 공개한다. 모델 transport는
public web transport와 공유되지 않고 다른 origin으로 인증 header를 redirect하지
않는다. `any`, TypeScript 검사 무시 지시, 추적된 secret·원본 archive·build 산출물은
발견되지 않았다. 이 검토는 실제 provider나 streaming runtime 검증이 아니다.
