## P06.1 구현 메모

- JSONL reader는 64KiB chunk만 읽고 record 수, line byte, page scan byte, JSON 깊이·node와
  경고 수를 각각 제한한다. page cursor에는 파일 identity와 offset을 넣어 교체·축소를
  거부하며, 거대한 손상 line을 건너뛰는 상태도 이어 받아 다음 page가 같은 위치에 멈추지 않는다.
- 줄바꿈으로 끝난 잘못된 중간 record와 줄바꿈 없이 끝난 마지막 record를 다른 경고로 반환한다.
  뒤의 정상 record는 계속 읽되 원본 line을 삭제·수정하지 않는다.
- writer는 배타 생성한 lock file의 무작위 token과 file identity를 보유한다. PID는 진단 정보일
  뿐 stale 판정이나 자동 삭제에 쓰지 않으며, 같은 process의 동시 append와 append 중 release도
  거부한다. 소유 token이 다른 lock은 제거하지 않는다.
- 저장 디렉터리와 파일 권한은 지원 환경에서 각각 0700·0600으로 강제하고 실패를 숨기지 않는다.
  append는 손상된 마지막 line이 있으면 분리용 줄바꿈 뒤에 새 versioned record를 기록하고
  file sync를 수행하므로 기존 byte를 덮어쓰지 않는다.
- session metadata schema에는 cwd, provider/profile/model, response ID와 parent 계보만 둔다.
  trust, credential과 승인 상태는 저장하지 않으며 transcript writer 소유자만 metadata를 갱신한다.
  알려진 secret과 credential 이름의 field 값은 JSONL 직렬화 전에 제한된 복제본에서 redaction한다.

## P06.2 구현 메모

- lifecycle service는 new/resume/continue/fork/rename과 metadata update를 같은 활성 handle
  소유권 아래에서 직렬화한다. resume은 canonical cwd와 provider/profile/model을 복원하지만
  trust·credential은 복원하지 않는다. agent coordinator의 maintenance lease를 잡는 동안에는
  새 run 획득도 차단되므로 전환·rewind 도중 run이 끼어들지 않는다.
- `persistence: none`은 저장된 세션을 재개해도 새 메모리 session ID를 만들고 디스크 writer나
  임시 prompt 파일을 만들지 않는다. record 수·개별 byte·전체 byte 상한에 도달하면 오래된
  source of truth를 조용히 버리지 않고 추가 기록을 거부하며 close에서 메모리와 관리 상태를
  비운다.
- fork는 source transcript를 page와 snapshot 상한 안에서 읽어 최근 `message`와 `compaction`
  record만 새 ID로 다시 기록한다. 과거 run ID, lifecycle, agent event, permission, task와
  checkpoint 기록은 복사하지 않고 target의 격리 상태를 먼저 초기화한다.
- rewind는 현재 handle의 session ID와 checkpoint 소유자가 같은지 확인하고 활성 run이 없을
  때만 기존 안전 복원을 호출한다. 복원 결과가 완전할 때만 checkpoint manager가 record를
  제거하며, 부분 실패와 transcript 기록 실패를 별도로 반환하고 shell/network/MCP가 복원되지
  않았음을 결과에 고정한다.
- close와 metadata update는 JSONL 두 파일을 원자 transaction으로 가장하지 않는다. 각 기록과
  lock/정리 결과를 구분해 반환하고 실패를 숨기지 않으며, 영구 resume 초기화 실패는 기존
  checkpoint ownership을 지우지 않는다.

## P06.3 구현 메모

- versioned transcript message codec은 core message와 tool result를 제한된 JSON 구조로
  정규화한다. assistant tool call은 모든 대응 result가 이름과 call ID까지 일치할 때만 하나의
  history unit으로 채택하며, incomplete·orphan·mismatch는 실행 가능한 모델 문맥에서 제외하고
  제한된 경고로 남긴다.
- 모델 projection은 append-only transcript를 source of truth로 유지한 채 최근의 완전한 대화
  unit부터 message·byte 상한 안에 넣는다. 과거 tool observation은 전체·개별 byte 예산 안에서
  redaction한 purpose-specific preview로 줄이고, 호출과 결과 쌍은 함께 남거나 함께 빠진다.
- 현재 실행에서 별도로 주입한 신뢰된 system message만 system role로 보낸다. 저장 transcript와
  compaction preserved message의 system role은 승격하지 않으며, 신뢰된 system 지침이 잘리거나
  projection 상한을 넘으면 빈 bounded 결과와 명시적 requirement를 반환한다.
- context window은 provider metadata를 우선하고 없을 때만 사용자 설정을 사용한다. 둘 다 없으면
  unknown으로 유지해 128k 같은 임의 기본값을 가정하지 않는다. 알려진 상한에는 기본 85% 자동
  compact threshold를 계산하고 source·projected token 추정값을 함께 반환한다.
- lifecycle의 transcript scanner는 영구 JSONL과 no-persistence 메모리에 같은 record callback
  계약을 제공한다. maintenance lease와 handle 직렬화를 소유한 동안에만 읽고, page·record·snapshot
  byte·cursor 반복과 손상 경고를 제한하므로 run이나 append가 중간에 끼어들지 않는다.
