new/resume/continue/fork/rename lifecycle, checkpoint 소유 rewind, 모델 context projection과

## P06.1 구현 메모

- JSONL reader는 64KiB chunk만 읽고 record 수, line byte, page scan byte, JSON 깊이·node와
  경고 수를 각각 제한한다. page cursor에는 파일 identity와 offset을 넣어 교체·축소를
  거부하며, 거대한 손상 line을 건너뛰는 상태도 이어 받아 다음 page가 같은 위치에 멈추지 않는다.
- 줄바꿈으로 끝난 잘못된 중간 record와 줄바꿈 없이 끝난 마지막 record를 다른 경고로 반환한다.
  뒤의 정상 record는 계속 읽되 원본 line을 삭제·수정하지 않는다.
- writer는 배타 생성한 lock file의 무작위 token과 file identity를 보유한다. PID는 진단 정보일
  뿐 stale 판정이나 자동 삭제에 쓰지 않으며, 같은 process의 동시 append와 append 중 release도
  거부한다. 소유 token이 다른 lock은 제거하지 않는다.
- 저장 디렉터리와 파일 권한은 지원 환경에서 각각 0700·0600으로 강제하고 실패를 숨기지 않는다.
  append는 손상된 마지막 line이 있으면 분리용 줄바꿈 뒤에 새 versioned record를 기록하고
  file sync를 수행하므로 기존 byte를 덮어쓰지 않는다.
- session metadata schema에는 cwd, provider/profile/model, response ID와 parent 계보만 둔다.
  trust, credential과 승인 상태는 저장하지 않으며 transcript writer 소유자만 metadata를 갱신한다.
  알려진 secret과 credential 이름의 field 값은 JSONL 직렬화 전에 제한된 복제본에서 redaction한다.
