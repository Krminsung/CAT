# [cat][P13] 통합·이관·사용 문서

## 범위

P12가 병합된 main에서 기능 matrix의 누락 연결을 한 차례 정리하고, 사용자가 직접 실행하는 기존
`.smileserv` 데이터의 비파괴 import와 한국어 사용 문서를 완성한다. 새 기능을 탐색하거나 실제 사용자
HOME을 읽지 않으며 앱·원격 provider·MCP·hook·이관 runtime은 실행하지 않는다.

P12는 검토 head `63e094ef314690731fb4c504d91ce4616487e655`를 PR #12에서 merge commit
`c3481e50dc0b5a8b9862d3a185cf7dd8d4f33859`로 병합했다. merge parent는
`05a02e75e795e8079b318b2168fc372c50025c7b`, `63e094ef314690731fb4c504d91ce4616487e655`이며
phase head와 merge tree는 `ec1ac37493f7408c2a40c7865012c5d68e282f87`로 같다. phase head 조상
관계와 `origin/main` 포함을 확인했고 병합 뒤 검사를 반복하지 않았다.

## P13.1 기능 matrix

- `BUILTIN_TOOL_NAMES` 18개와 실제 registry를 대조했다. read 3개, mutation 3개, agent control 2개,
  skill 1개, public web 2개, command/task 4개, MCP 관리 3개다.
- 비대화형 `--print`에서는 `request_user_input`만 등록하지 않아 registry가 17개가 되던 누락을
  보완한다. 이제 항상 등록하되 입력 port가 없으면 `user_input_unavailable`, `not_started`로 실패한다.
- slash 이름·정의·handler는 28개, capability는 12개다. 제품 조립 시 active 목록을 기준 상수와
  대조한다.
- provider 13개는 profile ID 상수와 exhaustive catalog, hook 8개는 event 상수와 앱/tool/stop 호출
  경계, MCP protocol 2개는 config·CLI·adapter factory가 같은 상수를 사용하는지 확인했다.
- CLI agent 옵션과 현재 `auth`, `mcp`, `worktree`, `ssh` 관리 dispatch가 실제 application controller로
  이어지는지 확인했다. legacy import 관리 진입점은 P13.2에서 추가한다.
- 자세한 이름과 구현 경계는 `docs/implementation/CONTRACTS.md`에 기록했다.

## P13.2 비파괴 legacy import

- `cat-tui migrate` 관리 명령을 추가했다. `--source`는 절대 경로만 받고 기본값은 실행 사용자의
  `~/.smileserv`다. source와 `CAT_HOME`이 같거나 중첩되면 원본 변경 가능성을 피하려고 중단한다.
- source root identity·소유권·private mode, credential/settings JSON과 session JSONL의 파일
  종류·symlink·크기·변경 여부를 bounded reader로 확인한다. credential·session 자료에는 private mode도
  요구한다. 이관 구현에는 source write/chmod/rename/unlink 경로가 없다.
- 설정은 대상 파일이 없을 때만 안전한 호환 subset을 새 schema로 쓴다. `permissionMode`,
  `allowedTools`, 승인, hook, MCP 실행 설정은 자동 이관하지 않고 원본에 남긴다.
- 기본 명령은 legacy credential 파일 내용을 읽지 않는다. `--include-credentials`가 있을 때만 두
  credential 파일을 읽고 13-provider catalog와 HTTPS endpoint에 맞는 profile을 만든다. 동일 이름의
  대상 profile은 덮어쓰지 않으며 외부 API 검증을 호출하지 않는다.
- legacy session은 source identity와 원본 ID에서 만든 결정적 `legacy_*` ID로 import한다. 대상 index나
  transcript와 충돌하면 건너뛴다. model history에 전달된 user/assistant는 새 message schema로 변환하고,
  숨김·미전달·도구 사용 중간 응답을 포함한 다른 record는 `legacy_record` event로 보존한다.
  source/세션/전체 크기와 record 수를 제한한다.
- `trusted-workspaces.json`과 기존 approval은 읽어 새 저장소에 쓰지 않는다. 결과 문구에도 trust·승인
  미이관과 원본 불변을 표시한다.
- 실제 사용자 HOME, 이관 command, credential, session runtime과 검증 명령은 실행하지 않았다.

## 검증 상태

P13의 `npm run check`는 아직 예약하거나 실행하지 않았다. 정적 검사와 모든 runtime은 미검증이다.
