# [cat][P14] 배포 컴파일·설치본

## 범위

P13이 병합된 main에서 내부 launcher, 고정 Node.js runtime manifest, 비재귀 packager와 비파괴 사용자
영역 installer를 구현한다. 모든 컴파일 입력을 고정한 뒤 `npm run build`를 단 한 번 실행하고, 그
`dist/`를 실행하지 않은 채 Linux x64/arm64 설치본으로 한 번 포장한다. 설치본·앱·Node bundle은 개발
중 실행하지 않으며 npm publish, GitHub Release와 공개 배포는 범위에 포함하지 않는다.

P13은 검토 head `471c5d3b597a5f89a3fccf1303c6f47e86b0b6c4`를 PR #13에서 merge commit
`7d1cc7809871bb09bf704daab71a73299233f7c3`으로 병합했다. merge parent는
`c3481e50dc0b5a8b9862d3a185cf7dd8d4f33859`, `471c5d3b597a5f89a3fccf1303c6f47e86b0b6c4`이며
phase head와 merge tree는 `591530b57ea8e1e1decbce6e2ede8664631833ff`로 같다. phase head 조상
관계와 `origin/main` 포함을 확인했고 병합 뒤 검사를 반복하지 않았다.

## P14.1 launcher와 runtime manifest

- npm 기본 bin은 Unix 기본 도구와 충돌하지 않는 `cat-tui`이고 설치 디렉터리 안의 실제 wrapper는
  `bin/cat`이다. PATH의 `cat` 연결은 installer에서 사용자가 별도로 선택할 때만 고려한다.
- wrapper는 최대 40개의 심볼릭 링크만 해석하고 설치 루트의 `dist/cli/main.js`만 실행한다. 설치본의
  `.runtime/node/bin/node`를 우선하며 소스 checkout에서는 package engine과 같은 Node.js 22.19.0
  이상만 허용한다. 내부 파일을 읽기 위해 시스템 `cat` 명령을 호출하지 않는다.
- bundle runtime은 Node.js 공식 자료에서 2026-09-11 현재 LTS로 표시된 v24.21.0(Krypton)으로
  고정했다. Linux x64와 arm64의 공식 `tar.xz` 파일명·정확한 URL·SHA-256을
  `packaging/runtime-manifest.json`에 기록했고 개발용 engine과 bundle runtime을 분리했다.
- 확인 출처: `https://nodejs.org/en/about/previous-releases`,
  `https://nodejs.org/download/release/v24.21.0/`,
  `https://nodejs.org/download/release/v24.21.0/SHASUMS256.txt`.
- 시스템 `cat`, Node bundle, 앱과 검증 명령은 실행하지 않았다.

## 검증 상태

P14의 유일한 `npm run build`는 아직 예약하거나 실행하지 않았다. 정적 검사와 모든 runtime은
미검증이다.
