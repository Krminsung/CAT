# P14.R09.UI — 터미널 가시성 개선

## 범위와 진행

2026-09-21 사용자 요청: 고양이 ASCII 시작 화면, 작업 중 로딩, 대화 역할 구분, 읽기 쉬운 세션
표시와 권한 팝업 겹침 개선. 앞선 시간 제한 제거 커밋 `8b6c75b8731901e3ffbe71611423ca7edeaf79d1`을
보존하고 같은 P14 후속 작업에 포함한다. 새 검증 단계로 이전 검사 예산을 초기화하지 않는다.

## 변경

- `presentation.ts`: 고양이·시작 안내, 대화 제목 머리글, 역할별 테두리·색상과 실행 상태 표시.
- `input.ts` / `screen.ts`: 실제 입력 처리의 busy 변경을 연결한다. 시작 인자 prompt와 일반 입력,
  세션 단축키 처리에도 로딩을 표시하고 종료·취소·오류·화면 닫기에서 timer를 정리한다.
- 모델 응답 대기/작성, 도구 실행, 다음 단계 판단, 사용자 확인, 압축과 결과 정리를 표시한다.
  텍스트 응답이 끝난 것은 전체 작업 완료로 취급하지 않는다. 완료와 오류·취소 표시를 구분한다.
- `transcript.ts`: 나/CAT 역할 이름과 서로 다른 세로선·색상, 메시지 사이 여백을 사용한다.
  표시 cache를 재사용하고 항목당 최대 512행 이후에는 생략 안내를 둔다. 원문 복사에는 장식을 넣지 않는다.
- `dialog.ts`: 불투명 전체 배경, 중앙 패널, 본문 페이지 스크롤과 고정 선택지·키 안내.
  작은 창에서는 보이지 않는 선택을 확인하지 않는다. 입력 패널의 커서·masked key 흐름은 유지한다.
- `application.ts`: 긴 세션 ID 대신 새 대화/첫 요청 제목을 표시하고 `/rename`·세션 전환과 연결한다.
  세션 선택 목록은 이름·날짜·짧은 보조 ID를 쓰며 실제 저장 ID와 재개 계약은 변경하지 않는다.
- 색상은 화면 boundary의 redaction/제어문자 제거 다음에만 생성한다. `--no-color`, `NO_COLOR`,
  `TERM=dumb`에서는 색상을 추가하지 않으며 역할·테두리·불투명 배경은 유지한다.
- 권한 정책·승인 빈도·자동 허용 범위, 실제 사용자 데이터와 Release/installer는 변경하지 않는다.

## 소스 검토

입력 busy의 true/finally false, run_end와 텍스트 종료의 구분, timer cleanup, modal focus·취소·
크기 변경, 입력 커서 표식, Unicode 표시 폭, redaction 뒤 색상 생성, session rename 호출을 읽어 검토했다.
신규 파일과 변경 diff를 확인했으며 정적 컴파일이나 런타임 결과로 표현하지 않는다.

## 검증 승인 대기

UI와 앞선 시간 제한 변경을 합친 `npm run build` 1회와 로컬 검증 1회를 요청했다.
아직 승인되지 않았으므로 build/check·앱 실행·테스트는 수행하지 않았다.
검증 시에는 임시 CAT_HOME과 로컬 모의 API만 사용하고 실제 계정·유료 외부 API는 사용하지 않는다.

확인할 범위:

1. 새 대화 ASCII, 한글·줄바꿈 메시지의 역할 구분과 첫 요청 제목, `/rename`·재개.
2. 응답 지연과 텍스트 종료 후 도구/다음 요청 동안 spinner·경과 시간이 유지되는지.
3. 완료·오류·Ctrl+C 취소 후 입력 복귀와 timer 정리.
4. 긴 권한 설명의 페이지 이동, 선택지·취소, 작은/좁은 창과 resize, 색상 끄기.
5. masked key 입력과 modal 종료 후 포커스·커서 복귀, raw 복사·JSON에 색상 미혼입.
6. 공통 실행 예산에서 시간 경과만으로 종료하지 않으며 사용자 취소·횟수 제한은 유지되는지.

실제 PTY/서버 UI는 현재 미검증이다. 소스 커밋만 준비하며 push·PR·main 병합·새 Release는 하지 않았다.
기존 공개 v0.1.3 installer에는 시간 제한 제거와 이번 UI 변경 모두 아직 반영되지 않았다.
