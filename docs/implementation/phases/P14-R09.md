# P14.R09 — 전체 작업의 고정 시간 제한 제거

## 범위와 승인

2026-09-21 사용자가 전체 작업의 고정 시간 제한 제거를 요청했다.
기준 main은 `94d46c6c11464ec7612abf9aeacca0790d74d212`이며 이전 P14.R08은 PR #18로
병합되고 v0.1.3으로 공개된 상태다. 이전 검증 결과나 실행 예산을 초기화하지 않는다.

## 변경

- 공통 run 예산에서 `wallClockMs`, 10분 타이머, 시간 비교와 `wall_clock` 종료 원인을 제거한다.
- 일반 실행, 자동·수동 compaction, 복구와 승인 대기 모두 전체 경과 시간으로 중단하지 않는다.
- JSON 결과의 `budget.deadlineAt` 필드는 `null`로 유지해 시간 제한 없음을 명시한다.
- 사용자 취소와 cleanup, 횟수 제한, 개별 요청·도구·hook·background timeout은 유지한다.
- 기준 문서 6.3·8.2, README와 D041에 바뀐 계약을 기록한다.

## 검증과 게시

변경 소스와 호출 계약을 읽어 검토했다.

- 소스 전체 검색에서 `wallClockMs`와 `wall_clock` 런타임 참조가 남지 않았음을 확인했다.
- `sameRunLimits`에서 제거한 필드 비교를 없애 사전 compaction 예산과 runner 예산의 계약을 맞췄다.
- 실행 예산의 `deadlineAt`을 숫자로 계산하는 내부 소비자가 없음을 확인했다. CLI의 JSON 변환은
  `null`을 지원하며 `Infinity` 같은 비 JSON 값을 넣지 않았다.
- 기존 caller abort listener와 cleanup 경로, 횟수 소진에 따른 abort는 보존했다.
- HTTP·도구·hook·background timeout 소스와 설치·패키징 입력은 변경하지 않았다.
- `git diff --check`에서 공백 오류가 없음을 확인했다. 이는 빌드나 실행 검증이 아니다.

추가 `npm run build` 1회와 고정 시간 제한 제거·취소·횟수
제한의 로컬 회귀 검증 1회를 요청했으며, 승인 전에는 컴파일이나 런타임 검증을 실행하지 않는다.
새 검사 예산을 임의로 만들지 않으며 실패 시 수정·재실행하지 않고 결과를 기록한다.

현재 빌드·런타임은 미검증이며 push·PR·main 병합·새 installer·공개 Release는 수행하지 않았다.
서버에 설치된 v0.1.3에는 아직 이 변경이 반영되지 않았다.

## 2026-09-21 후속 검증 결과

사용자 “실행하고 검증하세요” 승인에 따라 UI 변경과 합쳐 빌드 1회 및 로컬 검증 1회를 실행했다.
빌드는 통과했고, 공통 실행 예산의 시간 타이머 미등록·가상 시계 경과 독립성, 사용자 취소,
횟수 제한과 cleanup 검증도 통과했다. 실제 장시간 서버 운용 결과로 확대 해석하지 않는다.

실제 PTY 초기 설정은 통과했으나 이후 UI 시나리오에서 검증 스크립트가 표시가 보장되지 않는
중간 응답을 기다리다 중단됐다. 전체 검증 상태는 `BLOCKED_VERIFY`이며 재실행하지 않았다.
통과·미확인 항목과 증거, 추가 승인 요청은 [UI 검증 기록](P14-R09-UI.md)에 정리했다.
추가 빌드·패키징·원격 게시 없이 소스와 결과 기록만 로컬에 보존한다.

## 2026-09-21 최종 로컬 검증 상태

후속 UI 승인 상태 표시 수정은 추가 빌드를 통과했고, 별도로 승인받은 5차 로컬 PTY 실행은
초기 설정 및 남은 UI 시나리오를 통과했다. 시간 예산 모듈은 이전 성공 이후 변경하지 않았으며
기존 예산 검증 결과를 재사용했다. 현재 상태는 승인 범위 내 `VERIFIED`/`LOCAL_ONLY`다.
상세 시도 이력·검증 범위·미검증 환경은 [UI 검증 기록](P14-R09-UI.md)을 따른다.
실제 장시간 서버 운용이나 외부 API·새 설치본을 검증했다고 주장하지 않으며 배포하지 않았다.
