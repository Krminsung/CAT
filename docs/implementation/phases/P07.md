# [cat][P07] TUI core

## 범위

pi-tui alternate screen에 header, transcript, multiline editor와 status 영역을 분리하고,
Unicode 입력·단축키·stream/tool/plan 갱신·native selection·raw transcript 흐름을 연결한다.
원본 `src/tui.ts`와 `src/clipboard.ts`, 설치된 pi-tui 0.85.1의 타입과 구현 계약만 읽으며
원본 TUI나 테스트를 실행하지 않는다. CLI 조립과 slash command dispatch는 P08,
SSH/OSC52 bridge는 P12 범위로 남긴다.

P06은 PR #6의 head `5a0b32ed50faf6d32cd064052999039e71d44135`를 merge commit
`c434311e79ac2c112ea8ac08e31b5a320dff3e2f`로 병합했고 tree·부모·`origin/main`
정합성을 확인했다. 이 커밋이 P07의 기준 main이다.

## P07.1 구현 메모

- stdin과 stdout의 TTY 여부를 시작 전에 각각 검사한다. stderr 상태는 독립적으로 노출하고 진단은
  stdout 화면과 섞지 않는 plain stderr writer로 보낸다. 비TTY에서는 raw mode나 alternate screen을
  시작하지 않는다.
- pi-tui의 terminal resize callback과 명시적인 terminal-height `VStack`을 사용해 header 1행,
  follow-end transcript, 가변 multiline editor, status 1행을 분리한다. editor만 focus를 소유하고
  실제 입력·stream 도중 cursor 및 scroll 세부 계약은 다음 하위 작업에서 연결한다.
- 모든 표시 문자열과 구성 요소 출력은 byte·행·표시 폭을 제한하고 외부 ANSI/OSC/APC와 제어 문자를
  제거한다. editor의 pi-tui cursor marker만 한 개의 내부 표시 제어로 보존하며 mouse reporting과
  자동 selection copy는 시작부터 끈다.
- 시작 일부 실패, component render/input/mouse/invalidate 실패와 애플리케이션 예외는 최초 오류만
  보존하고 새 run을 만들지 않는다. 정상·오류 종료 모두 `preserveScreen`을 사용하며 raw mode,
  bracketed paste, mouse, autowrap, cursor, alternate-screen 복원을 멱등 경계에서 수행한다.
- 초기 transcript API도 항목·개별 byte·합계 byte·render row가 제한되어 있다. token/tool/plan별로
  전체 기록을 다시 조합하지 않는 증분 상태는 P07.3에서 이 경계 위에 구현한다.

P07.1 구현 중이다. 단계 검증은 아직 실행하지 않았고 실제 terminal에서 화면을 시작하지 않았다.
