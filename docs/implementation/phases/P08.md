# [cat][P08] CLI·slash 명령·overlay

## 범위

실제 `cat-tui` entrypoint에서 argv, 비대화형 출력, 단일 slash command registry, 선택·승인
overlay와 세션→trust→context→run→저장→종료 lifecycle을 연결한다. 원본
`src/cli.ts`, `src/tui.ts`, `src/auth.ts`의 해당 계약만 읽고 원본 앱·API·테스트는 실행하지 않는다.
AGENTS·skills·markdown command·hooks는 P09, MCP는 P10, background·worktree·SSH는 P12에 남긴다.

P07은 검토 head `2f7df0ef1fb1b02277a16c9df537722104206070`을 PR #7에서 merge commit
`4d91f4a4716831a488c3ebb4ed0d94e95cc06070`으로 병합했다. merge의 두 부모, tree,
phase head 조상 관계와 `origin/main` 포함을 확인했으며 병합 뒤 검사는 실행하지 않았다.

## P08.1 구현 메모

- 옵션 이름, 값, 중복, 크기와 enum을 제한하고 `--continue`/`--resume`, 구조화 출력/print,
  worktree/session 충돌을 사용법 오류로 구분한다. 알 수 없는 옵션을 prompt로 삼지 않는다.
- text 결과와 진단은 각각 stdout/stderr로 분리하고 JSON/stream JSON은 ANSI를 실행하지 않는
  한 줄 JSON record만 stdout에 쓴다. 구조·record·text 크기와 redaction 경계를 둔다.
- help/version과 관리 명령은 TUI를 만들지 않는 entrypoint 경로를 사용한다. 아직 P08.4에서
  연결하지 않은 agent lifecycle은 빈 성공 대신 명시적 오류를 반환한다.

## P08.2 구현 메모

- 28개 기본 명령의 이름, 설명, usage, 책임 capability와 unavailable 이유를 단일 불변 정의표에
  둔다. 이름 누락·중복과 정의 수 불일치는 registry 초기화 전에 거부한다.
- help·자동완성은 capability와 실제 handler가 모두 있는 명령에서 파생한다. 알려진 미래 명령은
  목록에 노출하지 않지만 직접 호출하면 단계별 unavailable 이유를 반환한다.
- `/name argument`와 `?` 별칭을 제한된 parser 하나로 해석하고, 알 수 없는 명령과 미연결 명령,
  handler가 처리한 명령을 구분한다.

## P08.3 구현 메모

- model/provider/profile/session/권한 선택과 정보 표시가 같은 bounded overlay를 사용한다. 선택지는
  개수·항목·전체 byte 상한과 고유 value를 확인하고 화면 출력 전에 제어 문자열과 secret을 제거한다.
- 승인 화면은 이번 호출·현재 세션·현재 프로젝트의 동일 규칙·거부를 구분하고, 질문 취소와 run
  abort를 `CancelledError`로 전달한다. config/status에는 허용된 설정 필드만, cost에는 알려진 token과
  가격 미상 상태만 표시한다.
- `auth setup`은 masked 입력으로 받은 API key를 transcript/history/CLI 출력에 남기지 않고 endpoint
  origin과 profile을 함께 저장한다. status/use/remove는 secret 없이 동작하며 custom endpoint와 HTTP
  허용은 명시적 인자를 요구한다. 개발 중 provider 검증 요청은 실행하지 않았다.

## P08.4 구현 메모

- session 선택과 workspace trust를 먼저 확정한 뒤 설정, credential-bound provider/model, bounded
  context와 agent run, transcript 저장, 화면·transport·session 종료를 하나의 composition root에서
  조립한다. resume은 cwd/provider/profile/model만 복원하고 trust·credential·승인 상태를 되살리지 않는다.
- `@file`은 `read_file`, `! command`는 `run_command`를 중앙 executor로만 호출한다. P12 전 background
  실행은 명시적으로 거부하며 직접 입력도 hard deny, workspace identity, permission과 abort 경계를
  건너뛰지 않는다. `#`와 `/init` 등 확장 기능은 P09 unavailable 상태를 유지한다.
- 활성 API key를 CLI·화면·영구/메모리 transcript redaction 경계에 등록하고, provider/profile 변경과
  compaction에서는 response ID를 초기화한다. 화면이 실행 중 오류로 닫히면 활성 입력을 취소하고
  완료를 기다린 뒤 session lock과 transport를 정리한다.

## 단계 정적 검토 보완

- `auth status --help`가 존재하지 않는 `PROFILE` 인자를 안내하지 않도록 명령별 usage를 바로잡았다.
  stream JSON과 TUI 도구 상세는 알려진 secret 문자열뿐 아니라 `api_key`, `authorization`, `token`,
  `password`, `cookie` 같은 민감 field의 값도 구조를 유지한 채 `[REDACTED]`로 표시한다.
- 큰따옴표 안의 command substitution도 고려해 단독 `&`를 보수적으로 background 실행으로 거부한다.
  provider/model 전환은 세션 metadata 갱신 자체가 성공하기 전에 runtime 정체성을 바꾸지 않으며,
  metadata 적용 뒤 transcript 기록만 실패한 경우에는 실제 적용 상태와 오류를 함께 유지한다.
- 이 보완은 `a1eb310fa94c9b96a2dd1eb5c0d32b750fd84526`에서 확정했다.

## 정적 코드 검토

`origin/main...a1eb310`의 전체 P08 diff를 한 차례 읽었다. argv 충돌·크기·출력 모드, 28개 명령의
단일 registry와 명시적 unavailable 처리, modal 선택·승인·masked auth, session 선택→trust→context→
run→저장→종료 조립, `@file`·`!`의 중앙 executor 경로, 취소·공유 budget·동적 redaction·project
approval의 filesystem identity 경계를 계약에 대조했다.

검토 보완 뒤 `origin/main`이 기준 `4d91f4a4716831a488c3ebb4ed0d94e95cc06070`과 같음을 다시
확인했다. agent 계층의 TUI import, 중앙 executor를 우회하는 직접 tool handler 호출, TypeScript 검사
무시, `any` 타입 우회, 변경된 package 검사 script, 추적된 secret·원본 archive·build 산출물과 GitHub
Actions workflow는 발견되지 않았다. 정적 검토만 수행했으며 실제 CLI, TUI, API key 입력, provider,
session I/O, 파일·셸 도구와 앱 런타임을 실행해 검증했다고 주장하지 않는다.
