## P14.R11.1 — 공통 언어 정리

- 공개 검색어의 secret 제거 후에만 NFC·띄어쓰기·대화 표현을 정리한다.
- 일반적인 한국어 요청·질문 표현은 목록으로 식별하고, 세 글자 이상의 표현에 한해
  동일 어간 또는 경어 틀 안의 한 글자 삽입·삭제·치환·인접 교환을 허용한다.
- 짧은 지명, 제품명, 버전, URL, 명령어를 fuzzy correction으로 바꾸지 않는다.
- 조사 처리와 원문 단어 매칭을 공통 함수로 분리한다. 영문 식별자는 단어 단위로 비교한다.
- 정규화로 알려진 secret이 다시 형성되는 경우 전송하지 않도록 재확인한다.
  NFC/NFD가 다른 보호 문자열도 같은 데이터로 판별한다.

## P14.R11.2 — 검색과 원문 판정 연결

- P14.R11.1 커밋: `bdba92356a619195e28e16d0b3950d468b402a3b`.
- 검색 결과와 원문 근거에서 동일한 언어 정리·조사 제거·단어 매칭을 사용한다.
  한글과 영문이 함께 있으면 한글 키워드를 버리던 기존 동작도 제거한다.
- 날씨 주제와 오늘/내일 같은 공통 표현은 지역 키워드에서 제외한다.
  `날시`는 날씨 질문의 흔한 표기로 인식하되 실제 원문에서는 정상 날씨 용어를 확인한다.
- 지역 없는 날씨 질문에서 대화 표현의 오타를 지역으로 오인하지 않고 지역을 질문한다.
- 날씨 근거는 원문 제목·본문에 남은 대상 키워드와 날씨 용어가 함께 있어야 한다.
  URL에만 들어 있는 검색어로 원문 관련성을 인정하지 않는다.
- 검색 결과 요약만으로 답변을 승인하지 않는다. 성공한 fetch의 비어 있지 않은 본문,
  그 원문의 실제 최종 URL 인용, 비신뢰 웹 데이터 경계를 유지한다.
- 외부 전송 금지, private context, 권한 거부, URL/DNS 검증, 반복 검색·복구 상한은 유지한다.
- 언어 정책의 금지·로컬 범위 판정도 NFC로 비교하되 URL 추출에는 원문을 사용한다.
  secret/민감 패턴 필터는 NFC 표현에도 적용하며, 검색 문구 정리 후 다시 알려진 secret을 확인한다.
- 문장 끝 마침표는 대화 표현 제거를 방해하지 않되, 도메인·식별자 내부를 요청 표현으로 지우지 않는다.

## 추가 승인 후 확인할 회귀 사례 (아직 실행하지 않음)

아래는 합격 결과가 아니라 이번 수정의 확인 항목이다. 실제 모델·실시간 웹의 결과를 보장하지 않는다.

| 입력/상황 | 확인할 계약 |
|---|---|
| `오늘 부산 날씨 어때요?` / `어떄요?` / `어때여?` | 같은 지역 키워드와 정상 날씨 원문·최종 URL로 답변 허용 |
| `부산 날씨 알려주세여` / `알려 주세여` / `알려주세욧` | 요청 표현의 오타·띄어쓰기를 원문에 요구하지 않음 |
| `부산의 날씨는 어떤가요?` / NFC·NFD 입력 | 조사·유니코드 표현이 달라도 부산 날씨를 찾음 |
| `오늘 날씨 어떄요?` / `내일 날시 알려주세여` | 없는 지역을 추정해 검색하지 않고 지역 질문 |
| `부산 weather 알려주세여` | 영문이 섞여도 부산 지역 조건 유지 |
| `부산 날씨`에 서울 날씨 원문 또는 부산 맛집 원문 | 잘못된 지역/주제 근거로 승인하지 않음 |
| 검색 요약만 존재 / fetch 실패 / 인용 없음 / 미조회 URL 인용 | 기존 근거 부족 처리 유지 |
| 웹 금지 / 알려진 secret 및 NFC·NFD 변형 / 권한 거부 | 언어 정리가 외부 전송·보안 정책을 넓히지 않음 |
| 제품·버전 식별자, 잘못 쓴 지명, 모호한 대상 | 다른 이름으로 임의 치환하거나 출처 일치를 느슨하게 하지 않음 |

범용 한국어 맞춤법 교정기나 의미 추론 모델을 추가한 것은 아니다. 여러 글자가 틀린 지명·제품명,
대상이 불분명한 질문까지 확정적으로 교정한다고 주장하지 않는다. 모호하면 기존 확인 질문 또는
근거 부족 경로를 사용하며 사용자 원문·대화 저장 내용은 변경하지 않는다.

## 소스 검토 결과와 다음 작업

공통 함수의 import 연결, 비밀정보 처리 순서, 지역 없는 질문, 검색 발견과 성공한 원문·최종 URL
인용의 구분, 정책 우선순위와 기존 복구 상한을 소스로 검토했다. `git diff --check`에서 공백 오류는
없었다. 이는 TypeScript 검사나 런타임 실행 결과가 아니다. 새 의존성·테스트 프레임워크·자동
runner를 추가하지 않았으며 앱·실시간 웹·모델 API·원격 설치본을 실행하거나 교체하지 않았다.

다음 실행에는 `npm run build` 추가 1회와, 위 오타·오인 방지·보안 사례 및 모델 응답→도구 결과→
최종 인용 판정 흐름을 포함한 격리된 로컬 회귀 검증 1회의 명시적 승인이 필요하다.
로컬 검증에는 모의 provider/원문을 사용하고 실제 유료 API와 사용자 자격·세션은 사용하지 않는다.
실시간 웹·실제 provider·전체 TUI·설치본 검증은 이 로컬 검증과 구분한다. 실행 실패 시 재시도하지 않는다.
빌드·회귀가 통과하기 전 push/PR/merge/release는 진행하지 않는다.
