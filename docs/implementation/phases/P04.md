# [cat][P04] 권한·파일 도구·foreground shell

## 범위

부작용보다 먼저 적용되는 중앙 도구 검증·권한 경계를 만들고, workspace 읽기와
변경, patch/checkpoint, foreground shell을 차례로 연결한다. 원본
`src/tools.ts`, `src/permissions.ts`, `src/security.ts`, `src/workspace.ts`,
`src/checkpoints.ts`, `src/tasks.ts`의 관련 계약만 읽으며 원본 테스트는 실행하지 않는다.

P03은 PR #3의 head `e0139944be247ef74c596cc67b6baaa95b2d0c07`을 merge commit
`3581145239fb622b647cb1d54fbe64c292ae8d7c`로 병합했고 tree·부모·`origin/main`
정합성을 확인했다. 이 커밋이 P04의 기준 main이다.

## P04.1 구현 메모

- 최종 built-in 이름 18개는 한 목록으로 고정하되, 현재 구현된 도구만 provider에
  노출한다.
- 등록된 handler는 module-private 저장소에 두고 provider에는 복제한 schema와 설명만
  제공한다. 실행은 `CentralToolExecutor.execute` 한 경로로만 진입한다.
- 입력은 제한된 built-in JSON schema dialect, byte·깊이·node 상한을 먼저 통과해야
  한다. 알 수 없는 도구와 잘못된 입력에서는 handler를 호출하지 않는다.
- workspace trust와 명시적 도구 차단, 도구별 hard preflight를 hook과 승인보다 먼저
  적용한다. P09 전에는 `implementation: none`인 명시적 no-op hook port만 사용한다.
- 승인 규칙은 도구·canonical workspace·도구별 실제 대상을 함께 해시한다. 거부 규칙은
  자동 모드, allow 목록, session/project 승인보다 먼저 적용한다. 비대화형 승인 요청은
  대기하지 않고 구조화된 거부 결과가 된다.
- handler 결과와 오류는 중앙에서 redaction하고 byte 상한을 적용한다. post hook 실패는
  이미 수행한 handler를 재실행하지 않고 별도 경고로 남긴다.

## P04.2 구현 메모

- path guard는 absolute path, `..`, NUL·제어 문자, workspace 밖 symlink, Git 내부와
  관리 worktree, 민감 저장소 및 hard-link alias를 차단한다. 생성 경로는 가장 가까운
  기존 부모의 canonical identity를 함께 보존한다.
- `list_files`는 디렉터리를 따라가는 symlink 없이 결정적인 순서로 순회하고 파일 수,
  탐색 항목 수와 직렬화 byte 상한을 각각 제한한다.
- `read_file`은 일반 파일 identity와 읽기 전후 metadata를 대조하고 최대 1 MB의 fatal
  UTF-8만 읽는다. 반환 본문은 byte 단위로 제한하며 긴 한 줄은 Unicode 문자 기준의
  `next_start_line`·`next_start_column`으로 이어 읽을 수 있다.
- `search_text`는 먼저 path guard를 통과한 최대 10,000개 후보만 `rg`에 직접 argv로
  전달한다. `rg`가 없으면 고정된 Node worker에서 같은 후보와 deadline으로 검색하여
  복잡한 정규식이 주 프로세스를 무기한 점유하지 않게 한다. 두 경로 모두 결과 수,
  process output과 최종 JSON 크기를 제한한다.
- 읽은 파일 digest는 session별 observation으로 남겨 후속 mutation의 외부 변경 감지에
  사용한다. 실제 filesystem 경쟁 조건을 완전히 제거했다고 주장하지 않는다.

## P04.3 구현 메모

- `edit_file`은 비어 있지 않은 `old_text`의 정확한 일치 개수를 센다. 여러 위치가
  일치하면 `replace_all=true` 또는 더 긴 문맥 없이는 변경하지 않으며, 기존 파일의
  session별 관찰 digest가 달라졌으면 다시 읽도록 거부한다.
- `write_file`은 기존 파일을 바꿀 때 `overwrite=true`를 요구한다. 변경 파일은 최대
  1 MB의 UTF-8로 제한하고, 같은 디렉터리의 배타적 임시 파일을 동기화한 뒤 rename하며
  기존 mode를 보존한다. 새 상위 디렉터리는 실제로 만든 경로만 기록한다.
- `apply_patch`는 최대 32개 파일의 custom patch 또는 표준 unified diff를 먼저 모두
  parse·경로 확인·내용 적용해 staging한다. 중복 canonical target, 모호한 문맥,
  잘못된 hunk 범위와 파일 이동은 실제 변경 전에 거부한다.
- checkpoint는 변경 전 존재 여부·내용·mode·digest와 session/run/tool 소유자를 기록하고,
  모든 예상 변경 결과를 확인한 뒤에만 완료한다. 일부 파일 적용, 취소 또는 원자적 쓰기
  실패 시 역순으로 복구하며 현재 내용이 예상 결과와 다르면 덮어쓰지 않는다.
- rollback 또는 rewind가 일부 실패하면 성공으로 바꾸거나 기록을 먼저 제거하지 않는다.
  관리 임시 파일은 경로와 digest가 모두 일치할 때만 제거하고, 새로 준비한 빈 디렉터리만
  정리 대상으로 유지한다. 이는 OS 전체에 대한 원자적 transaction이 아니다.
- 도구 결과에는 실제 변경 여부, checkpoint ID, 대상 파일, 제한된 diff와 잘림 byte 수를
  담는다. 빈 파일 생성·삭제도 diff header로 구분한다.

## P04.4 구현 메모

- `run_command`는 등록 시 canonical workspace와 device/inode identity를 보존하고 승인
  전·승인 후·handler 직전에 context와 다시 대조한다. 승인 범위에는 정확한 command,
  cwd, timeout, foreground 여부를 모두 넣는다.
- 명령은 `/bin/sh`에 `[-c, command]` argv로 직접 전달하고 별도 shell 옵션을 켜지 않는다.
  child environment는 명시된 소수의 locale·terminal·기본 실행 변수만 전달하며 모델 key,
  token, proxy, SSH agent와 언어별 주입 변수를 상속하지 않는다.
- hard policy는 `.cat`·`.smileserv`의 credential/profile/secret 경로와 설정에서 계산한
  사용자 지정 민감 경로의 직접 언급, root·home·workspace 전체 삭제, 장치 포맷과 강제
  Git 변경처럼 명백히 복구하기 어려운 명령을 승인보다 먼저 거부한다. 이 denylist와 cwd,
  environment 제한이 임의 프로그램의 파일·네트워크 접근을 완전히 격리하지는 않는다.
- foreground child는 POSIX에서 자신이 시작한 process group을 소유하고 취소, 1–300초
  timeout 또는 합산 1 MB 출력 상한에 도달하면 TERM 후 KILL 순서로 끝낸다. background=true는
  P12의 session별 task manager가 연결될 때까지 실행 전에 명시적 미지원 오류가 된다.
- exit code 0만 성공으로 반환한다. non-zero는 실행 실패, 시작 뒤 취소·timeout·출력 제한이나
  종료 상태 유실은 실행 여부 불명으로 남기며 stdout/stderr와 종료 정보를 redaction·출력
  상한이 적용되는 구조화된 오류 상세에 보존한다.

P04.4 구현 중이다. 단계 검증은 아직 실행하지 않았다.
